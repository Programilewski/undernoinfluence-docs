## 1. Findings raised unprompted

### 1.1 Site search still publishes the brand-to-venue link

`Venue::scopeSearch` matches product names and alternate names. After stripping, a venue page wouldn't say "Lech Free", but typing "Lech Free" in discovery would still list every venue that has it. That's the same information, one step removed. **Recommendation:** search stops matching branded product names (and their aliases); it keeps matching venue names, streets, districts, house drinks and shared recipes. Someone who types a brand gets the category instead: a search for "Lech" shows nothing brand-specific, and the empty state can suggest "piwo bezalkoholowe".

### 1.2 The discovery tile lists product names too

`VenuePresenter` builds each tile's category rows with the product names inside. It's the same rendering problem as the venue page, in a second place. The build must cover both, and the test must check every public surface, not just one view (§3).

### 1.3 The KCPU e-mail describes a service UNI isn't

It says the site lists "napoje bezalkoholowe i niskoalkoholowe", and question 2 asks about low-alcohol drinks, which the law counts as alcoholic. UNI lists nothing above 0,5% (`catalogue-excludes-actual-alcohol`, a permanent rule). If KCPU answers question 2, it answers about a different product. **The follow-up should correct it** in one sentence.

### 1.4 Shared recipe names carry alcohol words

"Gin z tonikiem bezalkoholowy" and "Hugo bezalkoholowe" are in the catalogue. These aren't brands, so the brand rule doesn't touch them, but they're the "symbol referring to alcohol" grey area the 18.10 e-mail didn't ask about. The style list has the same question ("gin 0%"). **One follow-up question covers both.** Until it's answered, they stay named: hiding them buys no certainty and takes away the most useful part of a drinks menu.

### 1.5 The brand decision needs its measurement before launch, not after

The record's revisit trigger is "the stay metric falls below the threshold". If the metric and the number aren't written down before launch, any result can be read as success or failure after the fact (course 5 of the crash courses). It's a ten-minute decision: §4 Q3.

## 2. Answers to your notes from today

**"With the amendment we fall below the threshold. How do we exceed it again?"** By making the brand-free line carry what the brand told people: the style, how much choice there is, and whether it's truly 0,0. Everything that was never a brand (house drinks, shared recipes) stays named. Brand-sharing 0.0 beers are the commodity on a menu (every Żabka has Lech Free), so what makes one venue worth choosing over another mostly survives.

**"We rejected the lawyer."** It wasn't written anywhere; it is now, dated 19.10, with a revisit before the first paying venue.

**"Weren't photos rejected for V1?"** Yes, twice. I was wrong to suggest them. They're now out beyond V1 for house drinks, and the leftover column is gone.

**"What if a brand starts an alcoholic line? Occam's razor."** That changed my recommendation. Stripping only the alcohol-sharing brands needed almost the same code plus a check that never ends, and the brand searches that mattered were beer brands, which are stripped either way. Strip-all at launch also keeps the easier direction open: adding names later is cheap, removing indexed names isn't.

**"A description like 'lager' could stay?"** Yes. A style belongs to no company. The one rule: no combination that points to a single product, so no origin ("irlandzki stout"), no packaging, no brand product words.

**"I sent the e-mail 8 days ago."** Eight days is nothing for a public body. Wait until about 18.11, which is also when the Senate's text should be known, then send one follow-up: the correction in 1.3 plus the question in 1.4.

## 3. What the build touches

Every public place a brand or branded product name reaches today, from the code:

| Place | What happens to it |
|---|---|
| Venue page product rows and brand chips (`venues/show`) | Category + style lines; no links to `/napoj` or `/marka` for branded products |
| Discovery tile rows (`VenuePresenter`) | Same lines |
| `/marka/{slug}` | Removed (404 or 410), not `noindex` |
| `/napoj/{slug}` for branded products | Removed; shared recipes keep theirs |
| Sitemap (`SitemapController`) | No brand or branded-drink URLs |
| Structured data (`VenueSchema`) | No product names that carry a brand |
| Page titles, descriptions, share cards | Checked by the test, not by eye |
| Site search (`Venue::scopeSearch`) | Stops matching branded products (§1.1) |
| Admin and owner panels | **Unchanged:** full names; not public |
| Products import | Gains a style column |

**The test that guards it:** render every public surface with a fixture brand whose name is unusual, and assert the name appears nowhere: venue page, tile, sitemap, JSON-LD, search results. One test for the whole rule, not one per view.

**Effort, roughly:** one session for the code and tests, plus data entry of a style per product, mostly beer and wine.
