### 1. Nine whole-city search templates

- **What:** `SourcingQueryTemplateSeeder` gains nine templates without `{district}`, each with a note saying it is **untested**:
  - `intitle:menu inbody:"0%" Warszawa`: "0%" is how 34 of the 69 lines read so far print the strength.
  - `intitle:karta inbody:bezalkoholowe Warszawa`
  - `"piwa bezalkoholowe" "wina bezalkoholowe" Warszawa`: the two section headings menus print most.
  - `mocktaile OR moktajle OR "koktajle bezalkoholowe" menu Warszawa`: cocktail headings as the menus spell them.
  - `mocktail OR "koktajle bezalkoholowe" karta Warszawa filetype:pdf`: templates 3 and 4 merged for the whole city.
  - `"aperol spritz 0%" OR "hugo 0%" OR "gin tonic 0%" menu Warszawa`: the house drinks most often printed with 0%.

- **How it runs:** a template without `{district}` is sent once per run, so all nine cost 9 Brave requests (~$0.05). Seeding again adds only new templates and never changes one edited in the admin.

### 6. Sites drawn by JavaScript are read from their metadata (committed, not pushed)

- **What:** the text a venue's page is checked against now also includes the page's meta description, `og:description`, `og:title` and its schema.org (JSON-LD) values. `SourcingDomainVerifier::describedText`.
- **Why:** salute21.com gives "ul. Marcina Kasprzaka 24A" only there; its body is empty until JavaScript runs, so the name-and-address check failed on a venue's own site. Source A's Warsaw check reads the same text, so it benefits too.
- **Checked:** a new test in `LicenceListSourceTest` (a page with an empty body and the address in JSON-LD is accepted), the 180 sourcing tests, and the live salute21.com (address and name now found). With it, run 10 would have found **9 sites of 20**.

### 7. Admin tables that scroll inside their own box (built, **not committed**)

- **What:** on admin list pages (Kandydaci, Biblioteka menu, Pozycje z menu and the rest), the table's body scrolls and the page does not; the column header row stays at the top of the box; filters, bulk actions and pagination stay on screen. A small script (`resources/js/admin-tables.js`) measures the space left in the window below what sits above the table and gives the box exactly that height, again after every filter opened, selection made or window resized. The theme (`resources/css/filament/panel/theme.css`) makes the box scroll and the header sticky. Loaded on the admin panel by a render hook (`AdminPanelProvider`), built by Vite (`vite.config.js`). Phones keep normal page scrolling.
- **Why:** Paweł asked for it: with 2,612 candidates, scrolling the whole page loses the filters and the headers. A first version (CSS only, a fixed share of the window) still let the page scroll; he asked for a height that stops the page scrolling entirely, which CSS alone can't do because what sits above the table changes size.
- **State:** assets built on the PC; the 161 admin tests pass with the render hook, but they don't run the script. **Not seen in a browser** (the PC's dev server was down and the admin needs a login). Paweł checks Kandydaci on the PC; then it is committed and shipped with the metadata fix as v0.1.14.

## Learning Path

- **Search operators.** `intitle:`, `inbody:`, `filetype:`, `OR` narrow what a search engine returns; Brave marks some as experimental and may drop them when few pages match. Search "Brave Search API search operators".
- **Page metadata and schema.org.** Many sites built with JavaScript put their name, address and opening hours in `<meta>` tags and JSON-LD for search engines; reading those is far lighter than running the page's JavaScript. Search "schema.org LocalBusiness JSON-LD address".
- **Measure, then prune.** Each template is a small experiment; its yield (venues per query) decides whether it stays. Search "search query yield precision recall".
- **Sticky headers and scroll containers.** A header sticks only inside the box that scrolls; that box needs a height, and when what surrounds it changes, the height has to be measured. Search "CSS position sticky table header scroll container".
