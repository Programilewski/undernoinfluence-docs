### 1. Admin lists use the whole screen (v0.1.14)

- **Full width:**
  - **What:** the admin panel (not the owner panel) no longer caps pages at a fixed width. Every list and form spreads across the window. Set in `AdminPanelProvider` (`maxContentWidth(Width::Full)`).
  - **Why:** Paweł works on a 2K monitor. Wide tables such as Kandydaci and Pozycje z menu scrolled sideways while half the screen sat empty.
- **Filters open, above the table, on one line:**
  - **What:** every admin table now shows its filters directly above the rows instead of behind a filter button's pop-up. They are split into two groups, separated by a thin divider:
    - **"Zawęź"**: dropdowns such as Status, Źródło, Rodzaj punktu.
    - **"Pokaż tylko"**: tick-box switches such as "Pełny adres, bez lokalu" and "Do akceptacji".
  - **How it looks:** the bar is lightly tinted so it reads as separate from the table. Each label sits beside its field, and the whole thing fits on one line wherever it can. "Wyczyść" is a small link.
  - **Where:** set once for all admin tables in `AdminPanelProvider` (`Table::configureUsing`), so a new table gets it without anyone remembering. The grouping is in the new `app/Support/AdminTableFilters.php`, and the styling in `resources/css/filament/panel/theme.css`.
  - **Removed:** Lokale's own collapsible filter layout, now redundant.
- **Why it took four rounds:** each round was Paweł's feedback on a screenshot.
  1. The filters were hidden in a pop-up.
  2. Once open, they were scattered and blended into the table.
  3. Once grouped, the spacing was too large.
  4. The finished version was to be minimal and on one line when it fits.
- **Tables scroll in their own box:** this is the 17.11 work, committed now that it has been seen in a browser. The rows scroll and the page does not. The column headers stay at the top, and the filters and pagination stay on screen.
- **Tests:** the new `tests/Feature/Admin/AdminLayoutTest.php` has six tests:
  - full width on list and create pages;
  - the table script is loaded;
  - filters sit above the table on Kandydaci, Pozycje z menu and Lokale;
  - the groups appear in order on Biblioteka menu;
  - Lokale shows only the choices group.
- **How it was checked before Paweł saw it:** pages rendered by the tests were screenshotted in a headless browser on the PC, so each round could be compared to his screenshots.

### 3. A street written with an initial is found (v0.1.15)

- **What:**
  - **The fault:** GUGiK, the state address service, returned "ulica Emilii Plater 53" for "E. Plater 53" with a low score (0.61). The second query by the register's street name never ran, because the check "is this the same address?" treated "E." as a word that has to appear.
  - **The fix:** a one-letter word now counts as matching when a returned word starts with that letter. Any other word must still match in full.
  - **Cache:** GUGiK's verdicts are cached for 30 days, so the cache was renewed (`gugik:v3`). Otherwise the stored "not found" for Czar i Gar would have survived.
  - **Where:** `app/Services/GugikGeocodingService.php`.
- **Why:** the permit register abbreviates first names ("E. Plater", "J. Pawła II", "K. Szymanowskiego"). Every such street would have needed fixing by hand.
- **Checked:**
  - Two new tests in `GugikGeocodingServiceTest`: "E. Plater" is found as "Emilii Plater". "K. Plater" is not accepted, because the initial must be the first letter of a word in the returned name.
  - A read-only geocode on the home server returned Czar i Gar in Śródmieście, "ulica Emilii Plater 53". The venue there **still has no pin**. Paweł has to press *Zgeokoduj ponownie* once in its edit page.

### 4. Source B tries a place's site again 3 and 10 days later, then stops (v0.1.15)

- **What:** when a site carrying the place's name in its domain doesn't answer, the place gets a next try in 3 days, then 10 days after that. After the third failure the note says no further automatic tries will happen, and only *Szukaj mimo to* searches again.
  - **The job:** a daily job at **05:00** runs the tries that are due, up to the usual cap of requests per run.
  - **How a retry works:** it sends the place's Brave query again, about $0.005. Brave's terms forbid keeping its results, so the earlier domain list can't be reused.
  - **The note:** the candidate's note shows the date and the count, e.g. "ponowna próba 21.11 (próba 1 z 3)".
  - **What resets:** a site found later resets the count.
  - **What gets no retry:** a dead domain without the place's name, and a rejected place.
- **Where:**
  - `FindVenueSiteAction` counts the dead name-carrying sites and sets the date.
  - The new job is `app/Jobs/QueueVenueSiteRetries.php`, scheduled in `routes/console.php`.
  - The delays are in `config/uni.php` (`site_retry_after_days: [3, 10]`).
  - `LicenceList::domainCarriesName` is the name test, now shared with the ranking of domains.
  - `SourcingDomainVerifier::readHomeAndContact` reports *why* a site failed, not just that it did.
- **Why:**
  - Zoli Pizzeria's own site timed out on 17.11, and the place was marked searched and never picked again.
  - Paweł asked for retries but a cap. A site that is down for good shouldn't be tried for a year.
  - Only a site carrying the place's name counts. A dead directory or map link is not worth a retry.
- **Tests:** five in `LicenceListSourceTest`:
  - the retry date and note;
  - no retry for a dead domain without the name;
  - three tries then stop, including that nothing is sent before the date is due;
  - a site back up on the second try becomes the place's site;
  - a rejected place is not retried.
- **Schema:** two columns on `sourcing_candidates`, `site_down_count` and `site_retry_at`. They were added by editing the create migration, as every change before production is. On the PC and the home server they were added by hand, so data was kept. `database/schema.md` was updated in the same commit and now counts 459 columns.

## Learning Path

- **Filament panel-wide table defaults.** `Table::configureUsing` sets defaults every table in a panel inherits, which is how one setting put every admin table's filters above its rows. Search "Filament configureUsing global settings".
- **Geocoding confidence scores.** An address service returns a match with a score; below a threshold UNI asks again in a different form rather than accepting a guess. Search "geocoding match accuracy score threshold".
- **Retry with backoff.** Waiting longer between each try (3 days, then 10) and stopping after a few is the standard way to handle something that is down without hammering it forever. Search "exponential backoff retry limit".
- **Not storing what you're not allowed to.** Brave's terms forbid keeping results, so a retry repeats the search instead of re-reading a saved list; the cost is a request, the gain is staying within the licence. Search "Brave Search API terms storing results".
