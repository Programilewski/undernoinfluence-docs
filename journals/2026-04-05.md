## What Was Built

### Laravel Project Bootstrap
- **What:** Fresh Laravel 13 install with Filament v5, Livewire v4, Tailwind v4.
- **Where:** Entire project scaffolding — `composer.json`, `vite.config.js`, `resources/css/app.css`, `resources/js/bootstrap.js`.
- **Why:** These are the chosen stack components for UNI. Filament handles the admin panel (OCR scanning, venue approvals, product CRUD) without needing to build custom admin UI. Livewire enables reactive UIs without a JS framework later.

### Basic Leaflet Map (`resources/views/map.blade.php` — initial version)
- **What:** A single full-screen Leaflet map loaded via CDN. CARTO dark tile layer. Venue pins from the database.
- **Where:** `map.blade.php`, `VenueController@index`, `routes/web.php` → `GET /`
- **Why:** The map is the core B2C product. Getting it working first validates the data pipeline (DB → controller → view → JS).
- **State at this point:** Raw inline CSS, no Tailwind, no navbar, no sidebar. Just the map.

### Filament Admin Panel
- **What:** Admin panel at `/admin` with three resources: Categories, Products, Venues.
- **Where:** `app/Filament/Resources/`
- **Why:** Admin panel is in Phase 1 scope for venue/product CRUD and future OCR menu scanning. Filament generates this from PHP class definitions — no custom HTML needed.

### Database Schema (initial)
- `venues` — id, name, slug, address, latitude, longitude, is_claimed
- `categories` — id, name, slug, icon_url
- `products` — id, name, brand, category_id, slug, attributes (JSONB)

### Logo + Inspiration Assets

- **Why:** Visual reference for the venue tile design.

## Decision Register

### CDN Leaflet vs npm Leaflet
- **Chosen:** CDN (at this point)
- **Rejected:** npm package
- **Why:** Fastest path to a working map. Later sessions moved to npm via Vite for proper bundling and cache control.
- **Status:** Superseded in the Apr 7 session — Leaflet is now loaded via Vite/npm.

### Filament for Admin vs Custom Admin
- **Chosen:** Filament v5
- **Rejected:** Custom-built admin panel
- **Why:** Building admin UI is not a competitive advantage for UNI. Filament gives CRUD, search, filters, and a nice UI out of the box. Time saved here goes into the B2C product.
- **Status:** Permanent decision for Phase 1.

### PostgreSQL vs MySQL
- **Chosen:** PostgreSQL
- **Why:** `ILIKE` for case-insensitive search, `JSONB` for the `products.attributes` column, PostGIS available if geodata queries become needed. Better for analytics workloads long-term.
- **Status:** Permanent.

## Learning Path

If this session raises questions you want to understand better:

- **Filament v5 basics:** `php artisan make:filament-resource` — read the generated Resource class. The `form()` method defines the create/edit form; `table()` defines the list view.
- **Leaflet.js:** [leafletjs.com/examples](https://leafletjs.com/examples.html) — start with the Quick Start Guide.
- **JSONB in PostgreSQL:** PostgreSQL docs on [JSON Types](https://www.postgresql.org/docs/current/datatype-json.html). `attributes` stores flexible product metadata (alcohol %, volume, etc.) without needing schema changes for each attribute.
- **Tailwind v4:** Key change from v3 — config is CSS-first, no `tailwind.config.js` needed. `@theme` in CSS replaces the config file.
