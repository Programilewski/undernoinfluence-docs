# 2026-05-18 — ABV Trust Model + Venue Taxonomy Implementation

## Session Overview

**Goal:** Implement the V1 plan created from the NIQ/IWSR/OPUS research discussion and the latest ABV/taxonomy decisions.

**Outcome:** The app now has a conservative ABV trust model, a strict `Tylko 0.0%` filter, product-level ABV labels, corrected public venue taxonomy, and tests proving the trust contract. Current fake/test products and venues were not carefully migrated; the schema change performs only coarse local cleanup so development data does not block the new model.

## What Was Built

### ABV Trust Model

**Files:** `app/Enums/ProductAbvStatus.php`, `app/Models/Product.php`, `database/migrations/2026_05_18_133702_implement_abv_status_and_v1_venue_taxonomy.php`, `database/migrations/2026_05_18_134530_tighten_verified_under_zero_five_abv_constraint.php`

Added four ABV states: `verified_zero`, `verified_under_0_5`, `verified_exact`, and `unknown`.

`products.abv` is now nullable and paired with `products.abv_status`. Database constraints enforce the trust contract:

- `unknown` requires `abv = null`
- `verified_zero` requires `abv = 0.0`
- `verified_under_0_5` accepts null or values greater than `0.0` and up to `0.5`
- `verified_exact` requires a non-null value from `0.0` to `0.5`
- `abv = 0.0` is blocked unless the status is `verified_zero`

The public product label now comes from the model: `0.0%`, `<=0.5%`, exact `{n}%`, or `bezalkoholowe, ABV do potwierdzenia`.

### Strict Zero Discovery

**Files:** `app/Livewire/DiscoveryPage.php`, `app/Services/Discovery/Filters.php`, `app/Services/Discovery/VenueQuery.php`, `resources/views/livewire/discovery-page.blade.php`, `app/Services/Analytics/DiscoveryAnalytics.php`

Added `strictZero` filter state with URL param `zero`. Discovery only includes venues with at least one product where `abv_status = verified_zero` and `abv = 0.0`.

The filter is visible on desktop and in the mobile map filter strip. Analytics now records `strict_zero_only`.

### Venue Profile Labels

**Files:** `resources/views/venues/show.blade.php`, `resources/views/venues/_category-card.blade.php`

Product rows now show ABV confidence labels. This keeps `bezalkoholowe` as the platform umbrella while making exact product trust visible.

### Venue Taxonomy

**Files:** `app/Enums/VenueType.php`, `database/factories/VenueFactory.php`, `database/seeders/*`, `app/Console/Commands/ImportOsmVenues.php`, `app/Filament/Imports/VenueImporter.php`, `database/data/warsaw-venues.json`

Public V1 venue types are now:

- `restauracja`
- `pub`
- `bar`

`inne` remains an internal admin/import fallback only. Old public buckets such as cafe, cinema, generic hotel, nightclub, and merged `bar_pub` are not V1 public taxonomy.

OSM mapping now keeps `bar` and `pub` separate. Hotel bars/restaurants should be classified by the actual public venue experience, not by the building.

### Admin and Import Guardrails

**Files:** `app/Filament/Resources/Products/Schemas/ProductForm.php`, `app/Filament/Resources/Products/Tables/ProductsTable.php`, `app/Filament/Imports/ProductImporter.php`, `app/Services/Actions/ApproveProductProposalAction.php`

Admin product forms and imports now collect `abv_status` and block invalid combinations. Product proposal approval creates products as `abv = null`, `abv_status = unknown` because proposals do not collect ABV yet.

## Decision Register

| Decision | Chosen | Rejected | Why |
|---|---|---|---|
| V1 ABV scope | Include `0.0%` and products up to `0.5%` | Only `0.0%` | Warsaw venues visibly carry both; excluding up-to-0.5 products would make venue pages incomplete. |
| Unknown ABV | Third state: `unknown` with public “ABV do potwierdzenia” | Default unknown to `0.0` or `<=0.5%` | Guessing ABV creates a trust failure. |
| Strict-zero eligibility | `verified_zero` plus `abv = 0.0` only | Frontend-only convention | This needs to be enforced in query/model/database behavior so it cannot drift. |
| Venue taxonomy | `restauracja`, `pub`, `bar`; `inne` internal | Merge `bar_pub`, add cafes/cinemas/hotels/events now | Bar and pub are real distinct concepts; cafes/cinemas/events are broader channel ideas, not V1 venue discovery fit. |
| Existing fake data | Coarse cleanup only | Careful backfill/migration | Current products and venues are fake/test data, so detailed preservation is not worth time. |

## Risk Register

| Risk | Mitigation |
|---|---|
| Admin/import users still enter bad ABV combinations | Filament validation, importer validation, and DB constraints now all enforce the same contract. |
| `<=0.5%` public label may feel less familiar than colloquial `<0.5%` | It is more honest because products can be exactly `0.5%`. Marketing copy can still use “bezalkoholowe” as the umbrella. |
| `inne` venues leak into public results | `inne` remains valid in DB for import/admin fallback, but should be reclassified before publication. |
