## What Was Built

### The Syncthing gate — the one that would have cost you the journals

Step 9 of the repository migration is `cd docs && git init`. That puts a git object store inside the folder Syncthing replicates continuously to the homeserver and your phone. Three machines writing to one git object store with no locking corrupts it.

`docs/.stignore` already carries `.git` as an ignore rule, and the comment above it was written in anticipation: *"docs/ has none today (the repo root does), but a nested repo here would otherwise be replicated file-by-file and corrupted."* But `obsidian-sync.md` records that Syncthing **does not sync `.stignore`** — ignore patterns are per-device, entered by hand. So one machine of three is protected, and the rule has never been tested against a folder that actually contains `.git`.

The migration plan is now version 4.0 and carries a gate: before `git init` in `docs/`, confirm `.git` is in the Ignore Patterns on the homeserver and on the phone. One minute, and it is the difference between a split and a disaster.
