## What Was Built

All in the application repository unless stated. In the order it happened.

### 1. CI green again (two causes, both outside the code)

- **The package clash.** Both pushes of 12.11 failed before a single test ran. The GitHub runner image ships `libpq-dev` 18.6; installing the PostgreSQL 18 client pulled it to 18.7, which now ships `/usr/bin/pg_config` — a file the PGDG repository's `postgresql-common` 293 also ships, so `dpkg` refused. Nothing in the job compiles against libpq, so `.github/workflows/tests.yml` removes `libpq-dev` first. The step carries a comment saying what happened and what to do next time; `.ai/rules/workflows.md` records the rule (a dpkg failure in CI is the runner image or the repository, not the application: read the dpkg line, drop the package we don't use, never `--force-overwrite`). **Why it matters:** a red CI blocks every deploy, because Deployer accepts only a CI-green tag.
- **The production `.env.example` in CI.** Once tests could run, two failed in CI and passed on the PC: CI copies `.env.example`, which since late October holds production's values (`APP_URL=https://…`), while the PC's `.env` is http. `phpunit.xml` now pins `APP_URL=http://localhost`; `.ai/rules/phpunit-xml.md` explains how to reproduce a CI-only failure locally (run the suite against a copy of `.env.example`). Full suite against a CI-style `.env`: green.

### 2. The home server, rebuilt (twice) and current

- Tagged **v0.1.7** and deployed; then `migrate:fresh --seed` for the create migrations edited on 28.10, 11.11 and 12.11. Paweł ran Ansible (poppler for PDF reading) and created his admin account.
- After the day's schema changes, tagged **v0.1.8** and deployed again. This time the user accounts were saved before `migrate:fresh --seed` and put back after, so Paweł's admin survived. The home server has the 7 search templates, the reference data and the two canaries; no candidates, no menus, and no Brave or Anthropic keys (its searches and readings will say the key is missing until it gets its own).
- At the end of the day, tagged **v0.1.9** (the reset button and the grouped menu, no schema change) and deployed without a rebuild: the PC and the home server run the same code.

### 3. The finder chose an old event menu over the current card

The Roof's sitemap led to a one-off World Cup page; its June PDF beat the full September card linked from the homepage by the 5 points every file earns for sitting on a "menu page". `MenuFinder` now sorts by the score without that bonus, then by the date in the file's address, then by the bonus — a newer card wins, and on an equal date the menu page's file still wins. Built from The Roof's real layout as a test. **Why:** the batch would otherwise have read a 2-drink event menu for a venue that serves 10.

### 4. Name and address read from the venue's own site

*Utwórz lokal* opened with an empty address, though the address check had already read the homepage and thrown the address away. New `VenueContactReader` (reads schema.org `PostalAddress` first, otherwise "street number, 0x-xxx Warszawa" in the text, footer included; the name from a schema.org business, `og:site_name` or the title's first part) and `VenueContactFinder` (the candidate's page, then the site's "Kontakt" page). *Znajdź menu* runs it; only empty fields are filled, so a correction is never overwritten. `sourcing_candidates.street_address` became `street_name`, `street_number`, `postal_code` and `address_source_url` (the page the address was actually read from, which is what *Źródło adresu* now shows). Later in the day, after Semolino: an address printed with a district instead of the city and no postal code ("ul. Obrzeżna 5a, Mokotów") now counts, and when a page prints its own address several times and other locations once (Pożaryskiego: 4 to 1), the dominant one wins. A page with two equally-printed addresses (a chain's homepage) still gives none.

### 5. A "mocktail" with a spirit in it

The World Cup menu's "Zapata's Fire Mocktail" lists sotol; both readings kept it as alcohol-free. Each reading now lists `alcoholic_ingredients` — ingredients normally alcoholic and not marked 0% or known to be alcohol-free — and the line keeps both readings' lists together (`menu_lines.alcoholic_ingredients`). A flagged line is never a "clean" case, so *Zatwierdź pewne* skips it; *Zatwierdź* on it asks for a confirmation naming the ingredient. The approval table shows the ingredient in red, sorts such lines last and can filter them. Dry run on The Roof's two PDFs: sotol, Lagg and Suze flagged; Lucano 0% and Sober Rum 0% not; Giffard Bitter flagged (probably a 0% syrup — a person decides). **Why:** publishing an alcoholic drink as alcohol-free is the one error the product cannot afford.

### 6. A search result must read as a venue

The batch's Brave candidates were 4 of 7 not venues — a trade journal, a brewers' association, a think tank and a Ukrainian site — because the check asked only for a Warsaw address, which every Warsaw institution has. `SourcingDomainVerifier::readsAsVenue` now also wants opening hours, a reservation or a schema.org restaurant/bar/café/hotel type, alongside a food or drink word; a page declaring a language other than Polish or English fails. Tested on the 7 and on 45 domains from venue searches: it dropped the four, a lifestyle magazine and a city portal, and no venue. Runs count **"Nie lokal"** beside "Bez adresu". Also: the address check now reads the contact page when the homepage has none (epoka.restaurant recovered) and accepts a phone printed without spaces ("+48455405300", Steam Bar).

### 7. Search queries became templates in the admin

Queries lived in `config/uni.php` (a deploy to change one) and their yield split into one row per district. New table `sourcing_query_templates` and admin page **Szablony zapytań**: add, edit, switch off with a note, never delete (a template's candidates are its yield). Each run keeps its queries' template ids, each candidate its template; the page and *Wydajność zapytań* add up domains, candidates, venues, rejections and drops per template, with its queries underneath. A template with 50 domains and no venue gets a **"Do wyłączenia?"** badge — a person decides. *Szukaj lokali* takes free-text **neighbourhoods** beside the districts. Seven templates are seeded, with notes from the day's measurements.

### 8. Brave tested against another model's advice

Paweł brought another model's query list. Tested on Brave: `intitle:menu "bezalkoholowe"` was the best form tried (4 venues of 13 domains) and is now a template; neighbourhoods beat districts in a small sample (Powiśle 2, Śródmieście 1) and are now a field; `-site:` exclusions changed nothing; `inurl:` returns nothing on Brave; brand-name `OR` lists found shops and producers, no venues. The original `"piwo bezalkoholowe" karta … filetype:pdf` query brought industry reports (0 venues of 11 domains) and was replaced with `… menu restauracja … -raport -badanie -konferencja` (3 of 20).

### 9. GUGiK: shortened, reversed and unit-numbered streets

Three real addresses wouldn't place on the map although GUGiK had found the right building:
- **"Rondo Daszyńskiego 2"** (The Roof): our check stripped "Rondo" from the register's street but not from ours. Both sides now lose the street-type word. The verdict is cached for days, so the cache key got a version.
- **"Pożaryskiego Mieczysława 35a/4U"** (Semolino Wawer): reversed name order, and a unit after the slash. A street now also matches when all its words are in the register's in any order, and a number with a unit is tried once more as the building.
- **"Woronicza 31"** (Semolino Qbik): scored 0.55 because the register's name is "Jana Pawła Woronicza", below the 0.7 minimum. When a low score has the same city, street words and number, the register's own name is asked once more and must clear the same 0.7 (it scores 0.84). The minimum is unchanged.

All six Semolino locations now geocode.

## Business Impact

Everything it got wrong was the kind of thing that costs admin time (an empty address on every venue, institutions in the candidate list, the wrong menu) or trust (a sotol "mocktail" passing as 0%). The search templates turn "which searches find venues" from a guess into a number per template, which is how the Brave spend stays small. Grouping the admin menu makes a batch one column of clicks instead of a hunt.

## Learning Path

- **Why CI fails when the code didn't change.** A CI job installs packages from outside sources on every run; when those change, the job breaks. Search "GitHub Actions apt dpkg trying to overwrite".
- **schema.org and JSON-LD.** The structured data many venue sites carry, which is where the address and venue type came from. Search "schema.org Restaurant PostalAddress JSON-LD".
- **Precision and recall.** The venue check trades a little recall (a real venue dropped) for precision (fewer institutions); measuring both on 45 domains is how that trade was checked. Search "precision vs recall explained".
- **Geocoding confidence scores.** Why a score alone can't be trusted, and why asking again with the register's own spelling is safer than lowering the bar. Search "geocoding match score threshold".
