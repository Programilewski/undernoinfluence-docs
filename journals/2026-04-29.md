## Decision Register

### Loading indicator: progress bar vs toast vs skeleton vs spinner

- **Chosen:** Thin CSS-animated progress bar above the venue cards, using `wire:loading`
- **Rejected option A:** Floating "Ładowanie…" toast — appeared/disappeared too fast, visually chaotic, old-fashioned
- **Rejected option B:** Fixed bar at viewport top — invisible behind the nav bar's z-index, confusing because it's disconnected from the content area
- **Rejected option C:** Alpine-based approach with `Livewire.hook('request')` — more complex, harder to debug, and `wire:loading` does the same thing natively
- **Rejected option D:** Skeleton loading state — too much work for the current phase, and the content loads fast enough that a brief progress bar suffices
- **Why the chosen approach:** `wire:loading` is built into Livewire, requires no JavaScript, and handles show/hide automatically. Absolute positioning prevents layout shift. The CSS animation provides visual progress feedback even though it's not tied to actual request progress — users perceive it as responsive.
- **Status:** Permanent.

### Category pill colours: per-category vs single accent colour

- **Chosen:** Per-category colours from `config/drinks.php` CSS variables, applied via inline `style` with `color-mix()` for subtle tinting
- **Rejected:** Single `accent` colour for all active pills (the previous implementation)
- **Why:** Per-category colours create a visual link between the filter pill and the drink icons/bars elsewhere in the UI. When you select "Piwo", the pill turns brown; "Wino" turns purple — instant recognition. The `color-mix()` at 15% opacity keeps it subtle enough that it doesn't look like a Christmas tree.
- **Status:** Permanent.

### Fake venue seeder: factory sequence vs explicit create loop

- **Chosen:** `Venue::factory()->count(30)->sequence(fn () => [...])` with explicit Warsaw coordinates
- **Rejected:** Relying on factory's `definition()` to derive coordinates from `city_id` — this didn't work because factory `definition()` runs before `sequence()` overrides
- **Why:** The factory computes lat/lng by selecting a random city and adding spread. Even when `city_id` is overridden by `sequence()`, the coordinates are already computed from the random city. Passing coordinates explicitly in the sequence is the only reliable way to ensure they're in Warsaw.
- **Status:** Permanent for the seeder. The factory's `definition()` remains unchanged (it's correct for general use).

## Session 3 — Venue Show Page Layout Redesign

## Session Overview

**Goal:** The venue show page (`/miejsce/{slug}`) was raw and unpolished — full-width layout with no content hierarchy, an oversized flat menu list, and on mobile the map was buried at the very bottom of the page instead of near the top where it's most useful.

**Outcome:** The venue show page was completely restructured across 4 iterative rounds. It now has a constrained width (`max-w-5xl`), clear section hierarchy with labelled dividers, a compact drink menu using collapsible category tiles in a 2-column grid, and most importantly — a responsive layout where the map appears right below the venue header on mobile (full-width, edge-to-edge) while staying as a sticky sidebar on desktop. Quick info (drink count, freshness badge) was moved into the header's subtitle row to keep the map card clean.

---

## What Was Built

### 1. Width Constraint + Section Hierarchy — `resources/views/venues/show.blade.php`

**What:** Replaced the full-width `app-container` wrapper with `max-w-5xl mx-auto px-4 md:px-8` to constrain the page to a readable width. Content was reorganised into distinct `<section>` blocks with `border-t border-ui pt-8` separators and `h2` headings styled as `text-xs font-black text-fg-faint uppercase tracking-widest`. The page now has 5 clearly labelled sections:
- Header (name, verified badge, venue type, district, drink count, freshness, address, description)
- Informacje (contact details + opening hours in a 2-column grid)
- Karta napojów (drink menu as collapsible category tiles)
- W pobliżu (nearby venue cards)
- Claim CTA

**Why:** The original page was a single flat stream of content with no visual breaks. You couldn't tell where "contact info" ended and "drink menu" began. The uppercase tracking-widest section labels match the design language used on the homepage's explainer section.

**Where:** `resources/views/venues/show.blade.php` — full rewrite of the `@section('content')` block.

### 2. Collapsible Category Tiles — `resources/views/venues/show.blade.php`

**What:** The drink menu was converted from a long vertical list to a 2-column grid of compact category tiles. Each tile shows:
- A coloured icon box (8×8 rounded square, using `color-mix()` with the category colour)
- Category name as bold text
- A count badge (colour-matched pill showing the number of products)
- A chevron toggle that rotates on open

Clicking a tile expands it to show the product list inline. When expanded, the tile spans both columns (`sm:col-span-2`). Products show name, brand (if present), and a compact freshness indicator (`Xd` instead of the old `X dni temu`). The expand/collapse uses Alpine's `x-show` with `x-transition.duration.200ms`.

**Why:** The old flat list was too tall — if a venue had 20 products across 5 categories, you'd scroll through all of them to get to "Nearby venues" or the share button. The tiles keep the menu section compact (~2 rows of tiles when collapsed) while letting interested users drill into any category. The 2-column grid matches the nearby venues grid, creating visual consistency.

**Where:** Lines 189–268 of `venues/show.blade.php`.

### 3. Mobile-First Map Placement — `resources/views/venues/show.blade.php`

**What:** The page uses `flex flex-col lg:grid lg:grid-cols-5` as its main container, with CSS `order-*` classes to control the mobile sequence. On mobile (flex column), the order is:
1. Header (`order-1`)
2. Map (`order-2`) — full-width, edge-to-edge
3. Contact & Hours (`order-3`)
4. Drink menu (`order-4`)
5. Actions (`order-5`)
6. Nearby venues (`order-6`)
7. Claim CTA (`order-7`)

On desktop (`lg:grid`), the map moves to the right column (`lg:col-span-2 lg:row-span-6`) as a sticky sidebar, and all other content flows in the left column (`lg:col-span-3`).

The map uses `-mx-4 w-[calc(100%+2rem)] md:-mx-8 md:w-[calc(100%+4rem)] lg:mx-0 lg:w-auto` to break out of the container padding on mobile, creating an edge-to-edge map that feels like a native app. On desktop, the negative margins reset and the map fits within its grid column with rounded corners and a border.

**Why:** On mobile, the map was dead last — after scrolling through the entire venue profile. But when someone visits a venue page, the map is one of the first things they want to see ("Where is this place?"). Moving it right below the name/address mirrors how Google Maps and TripAdvisor show venue pages. The edge-to-edge treatment on mobile makes the map feel expansive without the cramped padded look.

**Evolution during session:**
- Round 1: Map was in a nested left/right column wrapper — on mobile, the entire right column (with map) fell below the entire left column. Map was last.
- Round 2: Tried CSS `order` within the grid — the grid children are sections, not wrapped in columns, so `order` controls their position. But the map div didn't stretch to full width on mobile because it was still in the grid context.
- Round 3: Changed container to `flex flex-col lg:grid` so on mobile it's a flex column (where `order` and negative margins work naturally), and on desktop it's the grid.
- Round 4: Discovered that negative margins in flex column don't increase element width. Added explicit `w-[calc(100%+2rem)]` to match the negative margin offset. This was the fix that made the map visible on mobile.

**Where:** Lines 78, 130–147 of `venues/show.blade.php`.

### 4. Larger Map + Standalone Map Card — `resources/views/venues/show.blade.php`

**What:** Map height increased from `h-56 lg:h-64` to `h-72 lg:h-96` (~288px mobile, ~384px desktop). The "quick info" bar that was below the map (showing drink count, verified badge, freshness badge) was removed from the map card and moved into the header's subtitle row as inline badges. The map card is now just the venue image (if present) + the map — nothing else.

**Why:** The quick info bar was visual clutter on what should be a clean geographic element. The drink count and freshness status belong with the venue identity (the header), not with the map. The larger map gives users more geographic context — you can see surrounding streets and landmarks without zooming.

**Where:** Lines 94–109 (header with moved badges), lines 130–147 (standalone map card).

### 5. Leaflet `invalidateSize()` — `resources/views/venues/show.blade.php`

**What:** Added `setTimeout(() => map.invalidateSize(), 200)` after the Leaflet marker is placed.

**Why:** Leaflet calculates tile positions based on container size at initialization. With the new flex/grid layout, the container may not have its final dimensions when the `<script type="module">` runs. The delayed `invalidateSize()` forces Leaflet to recalculate after the CSS layout settles.

**Where:** Line 404 of `venues/show.blade.php`.

## Decision Register

### Venue page width: `max-w-7xl` (like homepage) vs `max-w-5xl` vs `max-w-4xl`

- **Chosen:** `max-w-5xl` (64rem / 1024px)
- **Rejected option A:** `max-w-7xl` (80rem / 1280px) — too wide for a focused read page. The venue profile has a single column of text content; at 7xl it would create uncomfortably long line lengths.
- **Rejected option B:** `max-w-4xl` (56rem / 896px) — too narrow for the 2-column grid (3/5 content + 2/5 map) to breathe. The map column needs at least ~350px.
- **Why:** 5xl gives enough room for the 2-column desktop layout while keeping the text content at a comfortable reading width (~600px left column).
- **Status:** Permanent.

### Menu layout: flat list vs collapsible tiles vs horizontal tabs

- **Chosen:** Collapsible tiles in a 2-column grid, collapsed by default
- **Rejected option A:** Flat vertical list (the original) — too tall, dominated the page, pushed actions/nearby below the fold
- **Rejected option B:** Horizontal tab bar — would require all categories visible at once, doesn't scale well on mobile with 5+ categories, and tabs imply "pages" not "sections"
- **Rejected option C:** Accordion (single-column collapsible) — wastes horizontal space, doesn't convey the "grid of options" mental model
- **Why:** The 2-column tile grid is compact when collapsed (you see all categories at a glance), informative (each tile shows the count), and expandable (click to see the full list). The tile-to-full-width expansion on open prevents products from being crammed into a half-width column.
- **Status:** Permanent.

### Mobile map placement: CSS order vs separate template blocks vs JavaScript

- **Chosen:** CSS `order-*` with `flex flex-col lg:grid` container
- **Rejected option A:** Duplicating the map HTML in two places (once for mobile position, once for desktop) — can't have two `#map` divs, and duplicating the Leaflet init would be wasteful
- **Rejected option B:** JavaScript-based DOM reordering on resize — fragile, causes layout flash, and Leaflet doesn't like being moved in the DOM
- **Rejected option C:** Pure CSS grid with `grid-template-areas` — would work but requires naming 7 areas across 2 breakpoints, more complex than needed
- **Why:** The `flex flex-col + order` approach on mobile is simple and works naturally. The `lg:grid` kicks in on desktop and CSS grid positioning takes over. The `order` classes are ignored in grid context because grid placement (`col-span`, `row-span`) takes precedence.
- **Status:** Permanent.

### Map full-width on mobile: negative margins vs closing/reopening container vs viewport units

- **Chosen:** `-mx-4 w-[calc(100%+2rem)]` to break out of container padding
- **Rejected option A:** Closing the `max-w-5xl px-4` container, rendering the map, then reopening — would break the grid layout that wraps all content for desktop
- **Rejected option B:** `w-screen -ml-[50vw] left-[50vw]` — classic full-bleed CSS trick, but causes horizontal scroll on pages with a scrollbar (scrollbar width not accounted for)
- **Why:** The `calc()` approach explicitly adds back the padding width that the negative margin removes. It's precise, doesn't cause scrollbar issues, and resets cleanly at `lg:` breakpoint with `lg:mx-0 lg:w-auto`.
- **Status:** Permanent.

### Quick info bar: below map vs in header vs in sidebar card

- **Chosen:** Inline in the header subtitle row (alongside venue type, district, middot separator)
- **Rejected option A:** Below the map as a card footer — added visual weight to what should be a clean map element, and the info (drink count, freshness) is about the venue identity, not the location
- **Rejected option B:** As a separate floating card on desktop — too many small cards, visual clutter
- **Why:** The header subtitle row already has venue type and district. Adding drink count and freshness badge there creates a single "at-a-glance identity line" — you see everything about the venue without scrolling. The middot separator keeps items visually distinct.
- **Status:** Permanent.
