## Learning Path

**`0.0.0.0` versus `127.0.0.1`.** A server told to listen on `127.0.0.1` answers only programs on the same machine. Told `0.0.0.0`, it answers on every network the machine is connected to — home Wi-Fi, Tailscale, anything. Development servers often default to the wider one for phone testing; the safer habit is narrow by default and wide on request, which is what `npm run dev:tailscale` already exists for.

**The `Secure` cookie flag.** A cookie marked `Secure` is only ever sent over HTTPS. Without the flag, a browser that is sent to `http://` first — a typed address, an old link — includes the cookie in that unencrypted request before the server redirects it. HSTS stops the browser from making that request at all, but only for as long as its max-age, which is why the flag matters most while HSTS is kept short. MDN, "Set-Cookie: Secure" and "Strict-Transport-Security".

**Why a correction has to be followed, not just made.** §2.7 is a small example of a general failure: a fact stated in three places, fixed in the one where the mistake was noticed. The habit that prevents it is searching the document for every other place the old claim appears before calling the correction done.

## Learning Path

**Database defaults and partial writes.** A column's default in the database applies whenever a write leaves that column out. Frameworks that fill only the fields they were given — Filament's importer, many forms — therefore inherit defaults silently. The defence is to set the values that must always hold at the moment of creation, in code, and to test through the real write path. Laravel docs, "Eloquent: Default attribute values"; Filament docs, "Import action — lifecycle hooks".

**Pivot tables and model events.** Eloquent fires events such as `created` and `deleted` for models, but attaching or detaching through a many-to-many relationship writes the joining table directly, and no event fires. Any follow-up has to be called explicitly, or the joining table has to become a model of its own. Laravel docs, "Eloquent: Relationships — many to many".

**Queued notifications and transactions.** A notification queued inside a database transaction can be sent before the transaction commits — or even if it rolls back. Sending after the commit keeps the message true. Laravel docs, "Notifications — queued notifications and database transactions".

**Whose consent is it?** Consent under the ePrivacy rules and GDPR belongs to the person it was asked of, and a cookie proves only what the browser holding it agreed to. A server acting on behalf of one person cannot use it to send data about another.
