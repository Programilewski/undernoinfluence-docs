## Decision Register

### 1. The PHP version is declared once, in the playbook, and every other copy is checked against it — **adopted, permanent**

Recorded: a-server-fact-is-declared-once-and-checked-everywhere-else.


**Chosen:** `php_version` in `ansible/group_vars/all.yml` is the source of truth, and a test fails if `deploy.php` or CI disagree. **Rejected:** making `deploy.php` read the playbook's file at deploy time. That would couple the deploy to a YAML parse and hide the version from anyone reading the recipe. Also rejected: leaving it, on the grounds that Ubuntu 26.04 ships 8.5 for its whole life. That's true today, but it's exactly the "works because nobody changed it" class this project keeps paying for. **Why:** the three copies each exist for a good reason, so the fix is to keep them honest rather than merge them.

### 2. Teaching documents live beside the commute files, on their own version track — **adopted**

**Chosen:** `commute-YYYY-MM-DD_N.md` with `version: 1.0 (own track)`, as `commute-2026-09-25_2.md` already did for "what UNI is". **Rejected:** a separate `learning/` or `tech/` file. You asked for them as commute files, they're read on the commute, and the index now labels them. **Why:** they're rewritten when the tool files change, not superseded by the next day's thinking, so they must not take a number in the commute sequence.

## Learning Path

- **Start with the two guides**, Ansible first (`commute-2026-09-30_2.md`), because Deployer assumes the server Ansible built. §4 of the Ansible guide is where they meet.
- **Single source of truth, and tests that enforce it.** When a value must be written in several places, pick one as the truth and make a test compare the rest to it. Today's PHP test is the pattern. Search: "single source of truth configuration drift".
- **Reading a tool's source.** `dep tree deploy` prints the real task list, and Deployer's recipe files are 20–100 lines each. Today's 24-step table came from them, not from the documentation.
- **Idempotence and atomic switches**, the two ideas the guides are built around. Search: "Ansible idempotency" and "atomic symlink deploy".
