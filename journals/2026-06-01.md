# 2026-06-01 — Removing OpenStreetMap & Simplifying Venue Curation

## Session Overview

**Goal:** After studying the OpenStreetMap **ODbL license** in detail, the founder decided to
*stop using OSM data* for seeding venues and to build the venue list **manually** instead. This
session removed every trace of OSM as a *data source* — code, database columns, workflow, and
the existing OSM-derived data — and simplified the venue admin around manual curation.

**Outcome:** Complete and fully tested (**513 tests passing**, Pint clean, `migrate:fresh --seed`
green). The app now has zero OSM *data* footprint. Venues live in a single admin screen gated by
one **Active** switch. Two things were deliberately kept because they are legally distinct from
ODbL data re-use and genuinely useful: the OSM/CARTO **map tiles** (display only, attributed) and
the **Nominatim/GUS geocoding** services (a service we call, not a database we re-publish).

## Decision Register

- **Stop using OSM as a venue data source (ODbL).** *Chosen* over continuing the importer.
  ODbL's share-alike/attribution obligations on a derived database are a legal burden and risk
  for our core asset. Manual curation yields clean, first-party data. **Status: permanent.**
- **Simplify the workflow (not keep, not fully gut).** Three options weighed. We learned the
  public site was already gated solely by `is_active`; the Draft→Ready→Published pipeline was
  triage bookkeeping for a 2,000-row machine dump. For one-at-a-time manual entry it added two
  confusing screens and dead bulk actions. *Chosen:* drop the pipeline, **keep the tools**
  (geocoding, map preview, completeness check) by relocating them. *Rejected:* "keep as-is"
  (needless complexity) and "delete entirely" (would lose useful address auto-fill). **Status: permanent.**
- **Keep OSM/CARTO map tiles + Nominatim/GUS geocoding.** *Chosen* over switching providers.
  Displaying rendered tiles (attributed) and calling a geocoding service are legally separate
  from re-publishing OSM *data*; switching to e.g. Mapbox adds cost/keys for no benefit.
  **Status: permanent (revisit only if usage policy/volume changes).**
- **Drop `is_permanently_closed` + other triage flags; keep `admin_notes`.** `is_active` already
  covers "don't show this." *Rejected:* keeping the flags (built only for OSM triage).
  **Status: revisit — trivial to re-add `is_permanently_closed` as a real state if needed.**
- **Edit migrations in place + `migrate:fresh`.** *Chosen* because this is a pre-launch dev DB
  with no production data. *Rejected:* additive "undo" migrations (unnecessary churn now).
  **Status: revisit — must switch to additive migrations once a production DB exists.**

## Business Impact

- **Legal risk removed.** Dropping OSM as a data source eliminates ODbL share-alike exposure on
  our core asset — the venue database is now cleanly first-party and freely licensable for B2B
  deals, partnerships, or future API products.
- **Data quality / trust.** UNI's brand is "the accurate alcohol-free directory." Hand-curated
  venues beat machine-imported skeletons (most OSM rows had no menu data). This directly supports
  the trust positioning needed for the June 2026 Warsaw launch.
- **Operational simplicity.** One admin screen + an Active switch is faster for a solo founder to
  operate than a two-stage review pipeline, with no loss of the address auto-fill that speeds entry.

## Learning Path

- **ODbL (Open Database License)** — why a *derived database* triggers share-alike, and why
  *using rendered map tiles* or *calling a geocoding API* does not. (openstreetmap.org/copyright)
- **`is_active` as a single source of truth** — collapsing a multi-status workflow into one boolean
  gate; when a state machine is over-engineering vs. genuinely needed.
- **Filament resource scoping** — `getEloquentQuery()` overrides control what a resource lists;
  removing one makes a resource show all records.
- **`migrate:fresh` vs. additive migrations** — the dev convenience vs. production safety trade-off.

## Session 2 — Brand Book, Favicon & Spec Freshness Check

### Session Overview
A short housekeeping session covering three things you asked for: a proper brand book,
fixing the browser-tab icon (it was still Laravel's), and a freshness audit of the V1
feature spec (SSOT) so it doesn't quietly go stale.

### What Was Built
1. **Brand Book** — `docs/brand/UNI-Brand-Book.md` (editable source) plus a designed,
   on-brand `UNI-Brand-Book.html` and a print-ready `UNI-Brand-Book.pdf` (4 pages, with
   real colour swatches and light/dark logo specimens). It documents the logo and its
   signature **NO.** gesture, the full colour system (brand violet, accent, the six
   drink-category colours, and the light/dark neutral tokens), typography (Inter + Brawler),
   dark-mode rules, and voice & tone. Every value is copied straight from
   `resources/css/app.css`, and the book states plainly that the CSS file is the source of
   truth — so the book can't drift from the product without it being obvious.
2. **Favicon fixed** — the tab was showing Laravel's icon because `public/favicon.ico` was
   an empty 0-byte file and nothing was linked in the page head. Generated a real icon set
   showing the **full wordmark** — "UNDER NO. INFLUENCE", with the violet **NO.** — on a
   rounded dark tile (`#141720`), matching how the logo reads on a dark surface:
   `favicon.svg`, a multi-size `favicon.ico` (32/48/64), `apple-touch-icon.png` (180px),
   and PWA icons (192/512px). Wired them into the site layout head and onto both Filament
   panels (`/admin`, `/panel`), so the brand shows up in the tab everywhere.
   **Also deleted** the stale orange `public/images/logo.png` (off-brand, unreferenced).
3. **SSOT freshness audit** — checked the V1 spec against the live app. Good news: it's
   substantially current (already reflects the recent OSM removal, Producers, GDPR
   erasure requests, ABV-status, and the Admin/Owner panel split). One real staleness:
   it said "24 Polish cities seeded" in three places, but the database now holds **25**
   (Sopot and Zakopane were added). Corrected all three, and bumped the spec's headline
   "as of" date from 2026-05-29 to 2026-06-01.

### Decision Register
- **Favicon = the full wordmark on a dark tile.** Initially built it as just the **NO.**
  mark (cleaner at 16px), but per founder direction the tab icon must be the *whole* logo —
  "UNDER NO. INFLUENCE" — so it's unmistakably the brand, not an abstract glyph. Built on a
  dark `#141720` tile so the white letters and violet NO. always have contrast regardless of
  the browser's light/dark chrome. Dropped 16px from the `.ico` (the wordmark is illegible
  that small); modern browsers use the crisp `favicon.svg` anyway.
- **Deleted the orange `public/images/logo.png`** — off-brand (the live logo uses the violet
  accent) and unreferenced anywhere in the codebase.
- **Brand book reads from the CSS tokens, not a parallel copy.** Avoids the classic
  brand-doc rot where the PDF and the product disagree. The book explicitly defers to
  `resources/css/app.css`.

- **Spec freshness is still manual.** Caught the city-count drift by hand. If the spec
  matters long-term, a tiny test asserting a few headline numbers (city count, district
