## Learning Path

**`--omit=dev` measures labels, not bundles.** `npm audit --omit=dev` asks *"what does `package.json` call a dependency?"* — not *"what reaches the browser?"* `axios` was filed under `devDependencies` and imported by shipped code, so the audit excluded the one vulnerable thing that actually shipped. The lesson generalises: a check that answers a slightly different question than the one you are asking is worse than no check, because it produces confidence.

**Retention is about columns, not tables.** GDPR Art. 5(1)(e) limits how long *personal data* may be kept for a purpose. A row is usually two facts glued together — one that identifies somebody and one that does not. Deleting the row to satisfy the article throws away the second for free. Nulling the identifying column satisfies the same article and keeps the rest.

**A flag is rarely the fix for a wrong condition.** The owner badge was gated behind a config flag because some rows looked wrong. The flag muted the badge for every venue, including correct ones, and left the condition untouched. When something displays wrongly, the question is what it is reading — not whether to stop displaying it.

**Fixtures are not evidence.** A state that only a factory can produce is a factory bug. Before treating a data state as a defect, trace every writer and ask whether production can create it. Here the answer was no, four times over, and all four guards already existed.
