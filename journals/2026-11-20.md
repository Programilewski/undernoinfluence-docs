## What Was Built

### v0.1.16 — a venue's type, suggested and confirmed

- **What:** each menu in *Utwórz lokale* gets its own type field. It is filled from the most trusted signal: the permit register's first word, then the two readings of the menu when they agree, then the schema.org type the venue's page declares. Every signal is shown under the field with its source and, for the menu, the line that decided it ("Piwa z kranu"). "Pomiń" leaves a menu for later; a menu with no signal must have its type chosen.
- **Why:** the 17.11 decision rejected guessing a type because a wrong guess would be invisible. A suggestion shown with its source and confirmed by a person is visible, so the 17.11 decision is superseded rather than broken.
- **The rules:** `VenueType::guidelines()`, in Polish, checked in order (hotel, kawiarnia, restauracja, pub, bar, inne), the menu deciding and never the name, with rules for the borderline cases. The same text folds out in the form and goes into the menu reader's prompt, so person and model can't drift apart.
- **Clubs:** a club in a batch is turned down with "Klub — UNI nie dodaje klubów", so the pipeline never proposes it again. The single form never fills one in. Source B no longer searches for register places that are clubs, and "Kluby" is gone from its kinds. A klubokawiarnia is not a club.
- **Biblioteka menu:** a "Lokal" column (the venue's name, the register's own description under it); the file type column is now "Format".
- **Cost:** the rules add about 1,150 input tokens to each of a menu's two readings, about $0.00023 a menu on Haiku 5.5. The estimate given in the conversation before building was about half that; it was measured after writing the rules.
- **Menus read before 20.11** get no signal from the menu reader until they are read again. A menu with any decided line can't be read again at all (`ReadMenuAction::refusalFor`); one with only waiting lines can, and the new reading replaces them. In the conversation this was first stated wrongly, as if a re-read brought decided lines back; checked in the code and corrected the same day.

### The timed round, defined

**START:** clicking *Utwórz lokale* on about 5 menus (the first in the list, not the easiest). **Lap 1:** venues created, types checked in the form. **Lap 2:** the last line of those menus decided in *Przegląd pozycji* (no "Pomiń"). **STOP:** every venue of the batch active, or deliberately dropped; fixing an address GUGiK missed counts. Paweł sends the three times and what slowed him; the counts come from the database, read-only. Before starting, the queue must hold no other menus' lines, or they mix into the timing.

**Corrected later the same day.** A venue goes live by itself once it has a map point and one approved line (`Venue::activateIfReady()`), so there is no separate STOP: the round ends at the last line of the batch. And Przegląd pozycji needs no stopwatch at all: every decision stores its second (`menu_lines.decided_at`), so the time per line comes from the gaps between decisions, with long pauses cut out. Only *Utwórz lokale* is half-measured: the submit is stored, the opening of the form is not. The queue does not have to be empty either: Przegląd shows the lines of menus with a venue first, so the batch is done when a line from another menu appears.

### v0.1.19 — Zapytaj AI in Przegląd pozycji

Paweł's first finding from the round: for a drink the catalogue lacks, Google brings shops that say little about who makes it, so he ends up asking a chat in another window and retyping. **"Zapytaj AI" (key I)** now does that inside Przegląd: it sends only the drink as printed (never the venue) to Haiku 5.5 with web search, and shows the brand, producer, product name, the strength a source states, whether it is alcohol-free, category, style, a note in Polish and up to three source links. The answer fills *Utwórz produkt*; a person still submits it. The same printed name on another menu reuses the answer at no cost. Tried live on two drinks before release: 7–13 s, one search, about $0.012 a line, and the model flagged its own doubt where sources disagreed (0.3% against the menu's 0.0%). Also a **"Kopiuj nazwę"** button that works without HTTPS, and the counter now says how many waiting lines belong to menus with a venue ("Czeka na decyzję: 78, z tego w menu z lokalem: …"), because 78 read as the batch. 1,560 tests, green; deployed. Record: a-model-identifies-a-drink-on-request-and-a-person-decides.

### v0.1.20 — a heading can vouch for strength

Paweł's first real use hit the strength guard: "Fines Bulles Vintense" printed under **"Wina bezalkoholowe"** could not become "Vintense Fines Bulles Blanc 0.0%", because the guard read only the printed name. The heading now counts for that one line. The bare spelling is still not kept as an alias, because on another menu it could be the alcoholic version, so the next menu that prints it still asks a person. A heading that says nothing about strength ("Piwa butelkowe") helps nothing, and the refusal now says what to do with an alcohol-free-only brand. Also, the AI had answered style "musujace" for a sparkling wine, a code that fits only still wine, so the form dropped it; the model now gets each style with the categories it fits, and a misfit is discarded. On a retry it left the style empty rather than guess white or rosé. 1,564 tests, green; deployed. Record: a-menu-heading-vouches-for-its-own-lines-strength.

## Learning Path

- **Web search as a model tool.** The model runs its own searches (billed per search, $10 per 1,000) and answers from the results; it's what a person does in a chat, inside one request. Search "Claude web search tool".
- **Strict tool schemas.** Making the model answer by "calling" a tool with a fixed shape guarantees the fields, which free text can't. Search "Claude strict tool use JSON schema".
- **Measuring from timestamps, not stopwatches.** Every decision already stores its second, so the gaps between them give time per line with pauses cut out, and no one has to remember to press a button. Search "event log time-on-task analysis".
