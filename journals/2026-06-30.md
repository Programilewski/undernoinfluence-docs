# 2026-06-30 — Front-End Polish (Map, Dark Theme, Filters) & a Code-Quality Cleanup

## Session Overview

Goal: a round of visual/UX polish on the public app, followed by a repo-wide
over-engineering audit and cleanup. Four UI areas were touched — the SSOT spec's
unreadable links, the venue-page map, the dark-theme colours, and the discovery
filter bar — then a "ponytail" audit found three pieces of dead/duplicated code
and we cut all three. No database schema changed. Full test suite green (407
passed) at the end.

---

## What Was Built

### 1. Venue page map — from a lonely dot to something that orients the user

**What changed:** The map on a venue page (`resources/views/venues/show.blade.php`,
`resources/js/venue-map.js`, `resources/js/map-config.js`) used CARTO's near-empty
"dark" basemap with a single anonymous pin — it told the user nothing. Now it uses
CARTO **Voyager** (labelled streets/POIs), the venue pin carries a name label and a
popup (address, freshness pill, "Nawiguj" link), and the **nearby alcohol-free
venues** we already load are plotted as secondary clickable pins that link to their
pages. Scoped to the venue page only; the discovery map is untouched.

**Why:** The map is a trust/orientation signal. A labelled map plus "here's what's
around you" turns dead space into a mini-discovery surface and adds internal links.

**Current state:** Live, assets rebuilt. One feature test added
(`venue_map_payload_includes_nearby_pin_coordinates`).

### 2. Dark theme — lifted off near-black, text softened

**What changed:** Dark `--color-base`/`--color-surface` were so close (contrast
~1.07:1) that cards melted into the background, and pure-white text on near-black
caused glare ("halation") that strains eyes in daylight. New "lifted slate" palette
in `resources/css/app.css` (and the stale `design-system.css` re-synced):
`base #15171E`, `surface #20242F`, `surface-hover #2B303D`, text `#E8EAEF`, border
12%. Cards now read as raised (~1.15:1); text dropped from ~19:1 to ~14.9:1 (still
AAA, no glare).

**Why:** Eye comfort for daytime use, and visible separation between background and
cards. Also fixed a pre-existing drift: `design-system.css` already intended an
off-white but the live `app.css` shipped pure `#ffffff`.

**Current state:** Live. (We tried a warmer variant and a lighter base mid-session;
the founder chose the cooler, slightly darker "lifted slate".)

### 3. Discovery filter bar — three fixes

**What changed (`resources/views/livewire/discovery-page.blade.php`):**
- **"Tylko 0.0%" is now the hero/premium filter** — gradient fill, a star icon, an
  accent border even when off; dropped the redundant `0.0` badge. It visually reads
  as the special one (the product's whole point).
- **Sort moved to a right-aligned bar just above the list** (with the result count),
  on both mobile and desktop — its natural home.
- **Fixed filters + scrolling list restored.** A regression had merged everything
  into one scroll container; the filters now stay put while only the cards scroll.
  Also fixed a layout bug where the "Tylko 0.0%" label wrapped to two lines and
  looked broken (`whitespace-nowrap` + `flex-wrap`).

**Current state:** Live, 41 discovery tests still pass.

### 4. SSOT spec links readable (`inspo/interactive_v1_feature_spec_SSOT.html`)

Internal spec doc only. Content links were browser-default blue/purple — invisible on
the dark background. Restyled to a teal (unvisited) / lavender (visited) with an
underline so the link cue survives regardless of colour. Cosmetic, internal.

### 5. Code-quality cleanup (ponytail audit → 3 cuts), net ~−160 lines

- **Deleted dead `config('uni.map')`** — bounds/zoom/tiles were never read in PHP;
  the JS (`map-config.js`) was already the only source of truth.
- **Deleted `CountryCodes::isValid()`** (no caller but its own test) and made
  `normalize()` private (only `label()` uses it).
- **Merged 4 geocoding actions → 2** behind a new `App\Contracts\Geocoder`. Both
  GUS and Nominatim services now `implement Geocoder` and **normalize their output**
  to one shape (`district_name`; reverse → `street/number/city/postcode/district`),
  so the actions are provider-agnostic. Callers pass the chosen provider, e.g.
  `new GeocodeVenueAction(app(GusGeocodingService::class))`.

## Decision Register

- **Dark palette → "lifted slate" (cool), not "warmer charcoal".** Both were applied
  live and compared. Rejected: pure-black bg / pure-white text (glare), and a lighter
  base (`#1C1F29`) which felt washed out.
- **Map → free Voyager tiles + nearby pins**, chosen over a static map image or a
  paid provider. Constraint honoured: V1 = no recurring spend. Known trade-off below.
- **0.0% filter styled as premium**; the redundant `0.0` badge removed.
- **Geocoding → normalize behind one `Geocoder` interface** rather than keep two
  near-identical action pairs.
- **Obsolete geocode tests repurposed, not deleted** — the repo rule forbids removing
  test files without approval, so the two `*NominatimActionTest` files were rewritten
  as provider-parity tests for the merged action (they still exercise the Nominatim path).

## Technical Debt Log

- **Voyager map tiles are light against the dark UI** — informative but aesthetically
  brighter than the surrounding dark theme. Acceptable for now; revisit if it grates.
  A dark *labelled* basemap would need a paid (EU pay-as-you-go) provider.
- **`EditVenue` still inlines reverse-geocode mapping**, duplicating
  `ReverseGeocodeVenueAction`. Left alone to avoid disturbing its form-refresh +
  notification logic. Could route through the merged action later.
- **Mobile discovery header is tall** now that filters are fixed — search + categories
  + toggles + freshness + sort eat screen before the list begins. Candidate for a
  collapsible "Filtry" sheet on phones.
- **`design-system.css` is not imported anywhere** (dead reference copy, kept in sync
  by hand). Either delete it or make it the real token source.
- The two `*NominatimActionTest` filenames now test the generic action — slightly
  misleading names retained to satisfy the no-delete rule.
