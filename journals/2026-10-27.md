### Learning Path

- **Fail closed, not open.** The public-name rule asks "is this a recipe?" rather than "does it have a brand?". When data is missing, the first question hides the name and the second shows it. Search for "fail-safe defaults" (Saltzer and Schroeder's design principles).
- **One source for every surface.** The venue page, tiles, structured data and the homepage demo all call `VenuePresenter::menuLines()`. One function changes, and every page changes with it. This is the "single source of truth" idea.
- **Test the rule, not the view.** `NoBrandNameIsPublishedTest` checks the outcome (the name appears nowhere) instead of how each page is built. Search for "property-based" and "invariant" testing for the wider idea.
- **Database checks as the last line.** The style list lives in the database too, so a script that bypasses the forms still can't write "irlandzki stout". Search for "PostgreSQL CHECK constraints".
