# 2026-05-15 — Production Readiness Audit

## Session Overview

**Goal:** Full production readiness audit — environment config, HTTPS, session security, trusted proxies, logging, mail, storage, scheduler, backups, build assets, crawlers, and .env hygiene.

**Outcome:** 15 issues identified across environment config, security, and infrastructure. 5 local-dev fixes applied. 4 production code changes documented (not committed — they would break local dev). 9 infrastructure items documented as a deploy-time checklist. SSOT updated with a new Production Readiness Audit section containing a dual-column local/production configuration matrix. Also corrected three stale "Documented" items (A7, A9, A10) in the API Audit SSOT section to "Fixed".

## What Was Applied (local-dev fixes)

### LF1 — APP_NAME fixed

`APP_NAME=Laravel` was the default across `.env` and `.env.example`. Changed to `"Under No Influence"`. This value appears in email sender names, browser tab titles, Filament panel headers, and Vite-injected meta. Correct for both environments.

### LF2 — DB password removed from .env.example

The real database password — the value is not repeated here, and it was rotated on 22.09.2026 — was committed in `.env.example`. Replaced with empty `DB_PASSWORD=`. The local `.env` still has the password (needed for dev). The password is in git history — it must be rotated before production.

### LF3 — SESSION_SECURE_COOKIE documented

Added `SESSION_SECURE_COOKIE=false` to `.env` (local) and `.env.example`. This makes the setting explicit. Must be `true` in production over HTTPS.

### LF4 — Storage symlink created

Created `public/storage` symlink pointing to `storage/app/public`. Needed for both local dev and production so uploaded images (product labels, venue photos) are served correctly.

### LF5 — Production baseline in .env.example

Added a commented "Production Baseline" section documenting every setting that must change for deployment: `APP_DEBUG=false`, `APP_ENV=production`, `LOG_LEVEL=warning`, `SESSION_ENCRYPT=true`, `SESSION_SECURE_COOKIE=true`, real SMTP, production domain, scheduler crontab, and queue worker command.

### SSOT updates — A7, A9, A10 status corrected

Three API Audit items (A7 query caps, A9 flash key, A10 map serializer cap) were marked "Documented" in the SSOT even though they were implemented in Session 6. Updated all three to "Fixed" with corrected descriptions.

## What Was Documented (production code changes — not committed)

These changes are needed before production but would break local development or are irrelevant locally. Documented in the SSOT with exact code to add at deploy time.

| ID | Area | File | Change |
|---|---|---|---|
| PC1 | HTTPS | `bootstrap/app.php` | Add `URL::forceScheme('https')` in `->booted()`, gated to production |
| PC2 | HTTPS | `bootstrap/app.php` | Add `$middleware->trustProxies(at: '*')` for reverse proxy support |
| PC3 | HTTPS | `SetSecurityHeaders.php` | Add HSTS header (`max-age=31536000`), gated to non-local |
| PC4 | SEO | `public/robots.txt` | Create with sitemap link and AI bot blocking |

These were initially committed and then reverted because we're in local development — the code changes would be dead weight (HTTPS forcing does nothing on HTTP, HSTS would be ignored, robots.txt has no crawlers to block, trust proxies has no proxy to trust).

## Decision Register

| Decision | Choice | Why |
|---|---|---|
| Production code changes | Document, don't commit | We're in local dev. HTTPS forcing, HSTS, trust proxies, and robots.txt are irrelevant locally and would add dead code paths to maintain. Apply them as a batch when preparing the production deploy. |
| Production baseline location | Commented block in `.env.example` | Keeps deployment docs co-located with the env template. A separate deploy doc would drift. |
| DB password in .env.example | Remove, keep in .env | `.env.example` is committed; `.env` is gitignored. The example file should never contain real secrets. |
