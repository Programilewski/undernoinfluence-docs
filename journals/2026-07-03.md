# 2026-07-03 — Spec Sync: SSOT Caught Up to the Mobile-Filter & Map Work

## Session Overview

Goal: bring the living spec (`inspo/interactive_v1_feature_spec_SSOT.html`) back
in line with the code as it actually stands today, then record the one real
product decision that the recent code embodies. This was a **documentation
session, not a build session** — no product code was written here. The app had
drifted ahead of the spec in four user-visible ways since the spec was last
touched (2026-06-30), all around the discovery filters and the venue-page map.

## What Was Built

### 1. SSOT spec synced to the current app (5 targeted edits, no rewrite)

The spec is ~7,000 lines and mostly accurate — rather than rewrite it, each real
gap was patched in place:

- **New "Discovery mobile filter overhaul" callout (Discovery section).** The
  mobile list view no longer shows every filter stacked above the list. Filters
  now collapse into a **bottom-sheet** you open with a "Filtry" button; a compact
  row above the list holds the result count, a dedicated mobile sort control, and
  a clear-all button that only shows when a filter is active. Desktop is
  unchanged (filters stay inline). Documented as shipped 2026-07-03.
- **Freshness pills colour scale (Filters section + callout).** The "how recently
  updated" pills on the list now run a green→lime→yellow→orange scale (fresh to
  stale) with a coloured dot and a clock icon, instead of a flat highlight.
- **Mobile map overlay note updated.** The quick-filter bar on the mobile *map*
  view now also carries the "Tylko 0.0%" toggle alongside the freshness and
  category pills — the spec said it didn't.
- **New "Venue-profile map enriched" callout (Venue Profile section).** The map
  on a venue page now has an accent frame and plots the venue *plus* nearby
  alcohol-free venues as clickable pins with popups (name, address, freshness,
  "Nawiguj"/"Zobacz lokal"), rather than one lonely dot.
- **"Nearby Venues" card cross-linked** to that map behaviour, and the "V1 Scope
  & State — as of…" date bumped to 2026-07-03 so the spec reads as current.

**Why:** The SSOT is the single source of truth we hand to anyone (a hire, an
investor, future-you). If it lags the product, it quietly becomes fiction and
stops being trustworthy. Keeping it honest is cheap now and expensive later.

**Deliberately left alone:** the geocoding refactor (the `Geocoder`
contract, the removed Nominatim action classes) is internal plumbing. The spec
describes the *feature* — GUS/Nominatim forward + reverse geocoding on the admin
edit page and bulk actions — which is still exactly true. No churn added there.

### 2. New decision record — mobile filter bottom-sheet

`inspo/UNI-Obsidian-Vault/uni-vault/decisions/product/mobile-filter-bottom-sheet.md`,
and a row added to the Decisions Log. Captures *why* the mobile filters collapse
into a sheet instead of sitting always-open. See Decision Register below.

---

## Decision Register

- **Mobile list filters collapse into a bottom-sheet; desktop stays inline.**
  On a phone the always-open filter wall pushed the first venue below the fold —
  the product felt like a form, not a map. Chosen: one "Filtry" toggle → a
  bottom-sheet, with sort + clear-all + result count in a slim row above the
  list. Rejected: keeping everything open (buries results), shrinking/truncating
  controls (hides filters people need), a full-screen filter page (loses the
  result-count context). Status: **Decided**, revisit post-V1 if mobile filter
  engagement turns out low.

- **Spec patched surgically, not rewritten.** Five in-place edits over a
  full pass, because the doc is largely correct and a rewrite risks introducing
  new errors while burning effort. Status: permanent working style for the SSOT.

## Business Impact

- **Mobile-first discovery.** Most real users arrive on a phone. Getting results
  above the fold instead of a filter wall is the difference between "this is a map
  I can use" and a bounce. Documented and decided so it doesn't quietly regress.
- **A spec that stays true is a sales/hiring asset.** The SSOT is what you show a
  prospective venue partner, a hire, or an investor to prove the product is real
  and thought-through. Every sync keeps that asset credible at zero code risk.
- **Debt paid down.** Two shortcuts from last session are gone (dead CSS, a
  duplicated admin action) — less to trip over when you next touch venue editing.
