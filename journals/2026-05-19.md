# 2026-05-19 — Venue Owner Deletion + GDPR Erasure Flow

## Session Overview

**Goal:** Make the venue/data deletion path clear and compliant enough that a venue owner is not blocked if they wants their venue and related data removed.

**Outcome:** The app now supports both self-service deletion from the owner panel and admin-managed email requests through `kontakt@undernoinfluence.pl`. The same erasure action powers both paths, so the operational behavior is consistent.

## What Was Built

### Owner Self-Service Erasure

Owners can now delete their claimed venue from the owner panel through a destructive confirmation action.

The flow:

- creates a `venue_erasure_requests` record;
- runs a shared `EraseVenueAction`;
- deletes the venue and related venue-owned records;
- deletes raw analytics `events` for that venue immediately;
- deletes uploaded venue/proposal files from the public disk;
- redacts related audit logs;
- sends a completion notification;
- optionally deletes the owner account too.

If the owner does not delete their account, their role is downgraded back to `user` when their last claimed venue is erased.

### Admin Email Request Flow

Admins now have a Filament `VenueErasureRequestResource` for deletion requests received by email.

The intended operational process:

1. Venue owner emails `kontakt@undernoinfluence.pl`.
2. Admin creates a request record, selects the venue, and records temporary verification notes.
3. Admin completes the request, which runs the same erasure action as self-service deletion.
4. The request is reduced to a minimal anonymous completion record.

Rejected requests require a reason and trigger a rejection notification.

## Decision Register

| Decision | Chosen | Why |
|---|---|---|
| Owner deletion mode | Immediate self-service erase | Avoids blocking legitimate removal requests and keeps the product posture privacy-forward. |
| Email request handling | Admin intake record | Email remains supported, but the app keeps enough process state to prove the request was handled. |
| Account deletion | Optional checkbox | Venue deletion and user-account deletion are related but not always the same request. |
| Retained record | Minimal anonymous completion record | Keeps operational accountability without retaining venue profile data, contact data, NIP, or raw analytics. |
| Admin venue deletion | Routed through erasure action | Prevents a plain Filament delete from bypassing file deletion, analytics cleanup, or audit redaction. |

## Data Model State

New table: `venue_erasure_requests`.

Important columns:

- `venue_id`, `requester_id`, `processed_by` are nullable and cleared on completion.
- `venue_name`, `requester_name`, `requester_email`, `request_note`, and `verification_notes` are temporary and cleared on completion.
- `source`: `self_service` or `email`.
- `status`: `pending`, `verified`, `completed`, `rejected`.
- `delete_account`: whether the requester also asked to delete the user account.
- `request_fingerprint`: non-identifying stable request marker.
- `due_at`: defaults to one month after request creation.

Migration added but not applied to the normal local development database in this session. It was exercised through the PHPUnit test database.

## Risk Register

| Risk | Mitigation |
|---|---|
| A venue owner deletes by mistake | The owner panel action requires destructive modal confirmation text. |
| Admin uses normal venue delete and bypasses erasure cleanup | Admin venue edit now uses the erasure action; venue bulk delete was removed. |
| Uploaded files remain after DB deletion | `EraseVenueAction` collects venue image, drink photos, and proposal label paths before deletion and deletes them from the public disk. |
| Raw analytics outlives an erasure request | Raw `events` rows for the venue are deleted immediately during erasure, separate from the normal 90-day prune. |
| Audit logs retain personal/venue data | Venue-linked audit logs are redacted to null actor/venue/auditable references and a minimal redaction marker. |
| Request records retain contact details | Completion clears requester and venue details from `venue_erasure_requests`. |

## Business Impact

- Venue owners now have a clear exit path, which reduces legal/compliance risk and makes the platform feel less extractive.
- The privacy policy and owner FAQ now match the operational behavior.
- The admin team has a repeatable process for email requests instead of an informal “delete manually” path.
- Analytics trust improves because erasure deletes raw venue-linked analytics immediately instead of waiting for general retention.
