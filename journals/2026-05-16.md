# 2026-05-16 — Map Marker Bug Fixed

## Session Overview

**Goal:** Fix map markers not appearing on the discovery page.

**Outcome:** Two bugs were found and fixed. Map markers now have a proper rendering surface and correct product counts.

## What Was Built

### Bug Fix 1: Map container had zero height (primary — markers invisible)

The discovery page uses a CSS flexbox chain to fill the full viewport: `body (flex flex-col, 100vh) → #main-content → discovery div (flex-1) → map pane → map div (h-full)`. Without an explicit height or `flex-1` on `#main-content`, the chain broke — every child collapsed to zero height, including the Leaflet map container. Leaflet rendered markers at coordinates that mapped to a 0×0 pixel area, making them invisible even though the data was correct and the JS was running fine.

**Fix:** Added page-scoped CSS in `discovery-page.blade.php`'s `@push('head')` block to give `#main-content` `display: flex; flex-direction: column; flex: 1 1 0%; min-height: 0; overflow: hidden`. This keeps the fix isolated to the discovery page and does not touch the shared layout.

### Bug Fix 2: `applyBestSort()` wiped `withCount` columns (secondary — wrong product counts)

`DiscoveryVenueQuery::applyBestSort()` called `->select('venues.*')` before adding its diversity subqueries. This reset the SELECT clause, removing the `products_count` and `drinks_count` subqueries added by `withCount()` earlier in the chain. All venues then showed `product_count: 0` on map pins (displaying the category count instead, so the visual impact was minor — but the data was wrong).

**Fix:** Removed `->select('venues.*')` from `applyBestSort()`. The base query already selects all venue columns; `selectSub` adds to the existing SELECT without resetting it.

## Decision Register

| Decision | Rationale |
|---|---|
| Fix CSS via `@push('head')` scoped style, not by editing the shared layout | The layout is used across all pages; adding flex classes to `#main-content` there could affect other page layouts unexpectedly |
| Remove `->select('venues.*')` rather than switching to `addSelect` | Removing it is cleaner — the base query already selects all columns; the line was redundant and harmful |

## Technical Debt Log

- **Resolved:** `applyBestSort()` SELECT reset — was silently returning `NULL` for `products_count` and `drinks_count` on every venue when sorted by "best". Now correctly returns the actual counts.
- **Existing:** The `#main-content` wrapper in `layouts/app.blade.php` has no classes at all, which is a fragile foundation for any full-height page. A future refactor could add a data attribute or class hook so full-height pages can opt in via CSS without scoped overrides.
