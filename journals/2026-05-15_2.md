# 2026-05-15 — Testability Hardening and Regression Coverage

## Session Overview

**Goal:** Turn the test coverage audit into implemented protections, not just a plan.

**Outcome:** The highest-priority testability work was implemented. Critical owner/admin moderation flows now have focused tests, several transaction-heavy Filament closures delegate to service action classes, analytics validation has a real regression test, OSM import edge cases are covered, and the SSOT was updated from "planned" to "shipped".

## What Was Built

### Product proposal moderation coverage

- Added `ProductProposalModerationTest`.
- Covers admin approval creating a catalog product.
- Confirms venue/product pivot creation with `added_by = proposal_approved`.
- Confirms venue freshness is updated.
- Confirms reviewer fields and audit logs are written.
- Confirms approve/reject actions are hidden once proposals are no longer pending.

### Owner product action coverage

- Added `OwnerProductActionsTest`.
- Covers owner attaching an existing catalog product to their own venue.
- Confirms attach updates freshness and breadth score.
- Confirms owners cannot reach another owner's venue edit page.
- Covers proposal form validation for missing name/category.
- Confirms owner product proposals write first-party audit logs.

### Policy tests

- Added `VenuePolicyTest`.
- Directly tests owner-only access to claimed venues.
- Tests admin `before()` override.
- Tests owner denial for create/delete.

### Validation and API regressions

- Added `ValidationAndApiRegressionTest`.
- Covers conditional venue-claim validation for new venue submissions.
- Confirms NIP and phone sanitization before claim creation.
- Confirms non-JSON analytics validation returns a bare `422`.
- Covers inaccuracy report note length, owner self-report denial, duplicate pending report validation, canary venue rejection, unknown category rejection, and analytics gateway failure handling.

### Command regressions

- Added `CommandRegressionTest`.
- Covers OSM import missing-file warnings.
- Covers duplicate OSM IDs.
- Covers center-coordinate import, Instagram normalization, district mapping, and inactive import defaults.
- Covers schedule registration for `uni:check-offer-freshness`.

### Testability refactor

The risky transaction-heavy logic was extracted out of Filament closures into service action classes:

- `ApproveProductProposalAction`
- `RejectProductProposalAction`
- `ApproveVenueClaimAction`
- `RejectVenueClaimAction`
- `AttachVenueProductAction`
- `DetachVenueProductAction`
- `SubmitProductProposalAction`

Filament still controls UI, notifications, and analytics capture, but business state changes now have direct testable entry points.

## Decision Register

| Decision | Choice | Why |
|---|---|---|
| Refactor scope | Small service action classes in `app/Services` | Avoids a new architecture layer while making the risky flows testable. |
| Filament closures | Keep UI notifications/analytics in closures | Those are UI-adjacent concerns; extracting only DB/audit transactions reduced blast radius. |
| Analytics invalid non-JSON payloads | Return `response('', 422)` via `HttpResponseException` | Previous `abort(422)` leaked a debug JSON body in tests/local debug mode. |
| OSM parser | Covered with command feature tests, parser extraction deferred | Good enough now; extracting a parser service is useful only when import logic grows further. |

## Technical Debt Log

- OSM parsing helpers still live inside the command. They are now covered by regression tests, but a parser service would be cleaner if imports become more important.
- Livewire/Filament code still uses some `app()` calls for analytics and action resolution. This is acceptable for now, but constructor injection would make dependencies clearer where framework lifecycle permits it.
- `DiscoveryFilters` and `DiscoveryVenueQuery` could still gain faster unit/service tests later. Current discovery coverage is broad but feature-test heavy.

## Risk Register

| Risk | Level | Mitigation |
|---|---|---|
| Refactoring moderation actions could change admin behavior | Medium | Existing `AdminClaimActionsTest` and `AuditLoggingTest` were rerun with the new tests. |
| Filament action tests may be sensitive to Filament internals | Low | Tests use documented `TestAction` helpers and current Filament 5 docs. |
| Bare 422 analytics response might affect clients expecting JSON from non-JSON requests | Low | JSON clients still receive JSON validation errors; only non-JSON callers get the bare response that was already intended. |

## Business Impact

- Owner and admin moderation flows now have stronger regression protection before real venues and owners depend on them.
- Audit logs are covered in the same flows that create business state changes, which helps production debugging.
- Import edge-case coverage reduces the risk of bad OSM data silently corrupting the seed pipeline.
- Policy tests make owner isolation easier to trust and easier to diagnose when it breaks.
