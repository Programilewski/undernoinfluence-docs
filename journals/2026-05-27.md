# 2026-05-27 — Brand Table Extraction & Admin Resource

## Session Overview

**Goal:** Extract the `products.brand` string column into a first-class `brands` table with its own CRUD resource in the admin panel.

**Outcome:** `brands` table created. Existing brand strings migrated with a FK back-link on `products`. `Brand` model added. Full `BrandResource` built in the admin panel. `ProductForm` and `ProductsTable` updated to use the relationship.

---

## What Was Built

### 1. `brands` Table & Migration

**Migration:** `2026_05_27_183729_create_brands_table.php`

```
brands: id, name (unique), country_code (char 2, nullable), website (nullable), timestamps
```

### 2. `products.brand` → `products.brand_id` Migration

**Migration:** `2026_05_27_183731_add_brand_id_to_products_table.php`

The `brand` string column on `products` was replaced with a `brand_id` FK. The migration:
1. Adds `brand_id` (nullable, FK → `brands.id`, `restrictOnDelete`)
2. Reads all distinct `brand` strings from `products`, inserts each as a row in `brands`, and back-fills `brand_id` on every product
3. Drops the `brand` string column

The `down()` path restores the string column and back-fills brand names from the joined table.

**Why `restrictOnDelete`:** Prevents accidental brand deletion while products are still attached. Admin must reassign or delete products first.

### 3. `Brand` Model

**File:** `app/Models/Brand.php`

`$guarded = []` with `hasMany(Product::class)`.

### 4. `BrandResource` (Admin Panel)

**Files:** `app/Filament/Admin/Resources/Brands/`

Table: name (searchable, sortable, bold), country_code, website (clickable URL, opens in new tab), products_count (aggregated via `->counts('products')`, sortable). Default sort by name.

Form: name (required, unique ignoring record), country_code (max 2, ISO 3166-1 alpha-2 helper text), website (URL validation).

### 5. `ProductForm` Updated

**File:** `app/Filament/Admin/Resources/Products/Schemas/ProductForm.php`

`brand` string field replaced with `brand_id` `Select` using `->relationship('brand', 'name')`. Supports typeahead search, preload, and inline create (name, country_code, website) without leaving the product form.

### 6. `ProductsTable` Updated

**File:** `app/Filament/Admin/Resources/Products/Tables/ProductsTable.php`

Column changed from `TextColumn::make('brand')` to `TextColumn::make('brand.name')`.

## Decision Register

| Decision | Chosen | Rejected | Why | Status |
|---|---|---|---|---|
| Brand as first-class table | `brands` FK + `BrandResource` | Keep `products.brand` as string | String brands can't carry metadata (country, website), can't be deduplicated or searched independently, and drift silently ("Heineken" vs "Heineken B.V."). A first-class entity enables enrichment and future brand-level analytics. | Permanent |
| `restrictOnDelete` on `brand_id` FK | Restrict | Cascade / SetNull | Cascade would silently orphan products. SetNull would lose brand attribution. Restrict forces explicit reassignment — the right safeguard for catalog data. | Permanent |
| Inline brand creation in ProductForm | Yes | Separate create flow | Admin can add a new brand without navigating away from product create/edit. Filament's `->createOptionForm()` makes this zero-friction. | Permanent |
