## What Was Changed

### 1. Admin Venue Analytics Tests Fixed

**Files:**
- `tests/Feature/AdminVenueAnalyticsPageTest.php`
- `tests/Feature/AdminVenueListAnalyticsTest.php`

The admin Venues resource intentionally scopes records to `seeding_status = published`, because the public Venues tab is now the live-site view while the Seeding Queue owns draft/ready/skip records.

The tests were still creating default draft venues, so Filament correctly could not resolve them through the published-only admin resource query. The tests now create published venues for the analytics page and list-row analytics actions.

**Result:** The focused admin analytics/list tests pass again.

---

### 2. Robots Output Fixed

**File:** `resources/views/robots.blade.php`

The robots template was malformed because directives were collapsed onto one line. It now renders a valid multiline robots file:

- Blocks AI training crawlers.
- Allows normal public indexing.
- Disallows `/admin/` and `/api/`.
- Links to the routed sitemap through `route('sitemap')`.

**Production note:** The production `APP_URL` still matters because it determines the absolute sitemap URL rendered inside robots.

---

### 3. RealVenueSeeder Fixed for the Current Product Model

**File:** `database/seeders/RealVenueSeeder.php`

`RealVenueSeeder` was still writing the removed `products.brand` string column. It now creates/reuses `Brand` records and writes `brand_id`, matching the current schema.

It also sets real seeded venues to `SeedingStatus::Published`, which matches the intended purpose of the seeder: creating real public launch venues instead of hidden draft queue records.

## Decision Register

### English Support in V1

**Decision:** Polish-first for V1. Do not add full English support before the Warsaw launch.

**Reasoning:** The V1 launch risk is not language coverage; it is data quality, operations, trust, and repeatable venue onboarding. English support adds copy, routing, SEO, QA, and support surface area. It is better handled after the Polish launch proves demand.

**Recommended posture:** Keep the architecture ready for future localization, but do not split the first release across two languages.
