# 2026-07-06 — Homepage Hero: Iterated the "Business Card," Landed on Abstract Brand Art

## Session Overview

Goal: fix the **homepage hero's right side** — the first thing every visitor
sees, and it read "empty and amateur." The old version was three cards pinned to
the corners of a half-empty box, filled with **hardcoded fake venue names**
("Craft Room", "Bar na Mokotowie", "Herbaciarnia") and a purple chip that just
repeated the venue count already shown on the left.

This was a **build + design-iteration session**. We explored several directions
with live screenshots and converged on an **abstract, low-fidelity "brand art"**
graphic — a cluster of skeleton venue cards carrying real drink-category colours,
layered with depth over an animated map mesh. No literal text, so nothing can
ever look like fake data.

We then built a fully-specified alternative — an **animated stack of three real
venue tiles** (top-3 by breadth score, cached, with a reveal animation) — got it
working end to end, and **reverted it** at your request, keeping the abstract
version. The final hero is committed as `hero v2`.

The reverted feature was not wasted: it surfaced a **real production caching bug**
(below) that we'll hit again the next time we cache database records, and the fix
pattern is now documented.

## What Was Built

### 1. Hero right side: fake-name cards → abstract brand-art cluster *(kept)*

`resources/views/home.blade.php`

The right half of the hero is now a cluster of three **low-fidelity "ghost"
cards** — rounded card shapes with skeleton bars where a name/pills would be, and
rows of **real drink-category colours** (piwo amber, wino magenta, drinki cyan,
etc.) as dots and mini "dot-meters." They're layered with depth: one sharp in
front, two scaled-down, rotated, and blurred behind. It floats over the animated
map mesh (grid + radar pings + faint category pins).

**Why:** The hero is the product's business card. The old fake venue names read as
a placeholder demo and undercut the "hand-verified, real data" promise. An
abstract treatment with **no literal text** removes the fake-data problem
entirely while still reading as "a colourful map of alcohol-free venues." It fills
the previously-empty space and looks intentional rather than unfinished.

**Current state:** live and committed. Desktop-only (`hidden lg:flex`), matching
the existing hero behaviour — the graphic does not render on phones, which
protects mobile load speed (the headline is the important element there).

### 2. Map mesh partial revived and bug-fixed *(kept)*

`resources/views/partials/home-mesh.blade.php`

This partial (an animated perspective grid with radar "ping" rings and small
drink-category pins) existed but was **never actually rendered** anywhere. We
turned it into the backdrop for the hero. In doing so we found a **latent bug**:
its category pins used Tailwind classes built from PHP values
(`top-[{{ $x }}]`, `w-{{ $size }}`) — a pattern Tailwind's build step **cannot
see**, so those pins would have silently rendered at the wrong size/position (or
invisibly). Rewrote them to use inline styles, which always work.

**Why it matters:** the bug was dormant only because the partial was unused. The
moment it was shown, it would have looked broken. Fixed for good.

### 3. Homepage smoke tests *(kept)*

`tests/Feature/HomePageTest.php` (new file)

Three tests that assert the homepage renders (HTTP 200) **with** venues and
categories, **without** venues, and **without** categories. The last one guards a
real edge: the decorative hero indexes into the category list and must not crash
when that list is empty.

**Why:** the homepage had no test at all. These are cheap insurance that a future
change to the hero or its data doesn't white-screen the front page.

### 4. Animated stack of three real venue tiles *(built, then reverted)*

Built to spec and verified working, then removed at your request. What it did,
for the record:

- **Data:** top 3 active venues by `breadth_score`, cached one hour.
- **Reused the real venue tile** component for authenticity.
- **Layout:** two faded, rotated, non-interactive tiles behind one sharp,
  clickable front tile linking to that venue's page.
- **Animation (front tile only, once, under 3s):** category swatches faded in
  staggered; the product-count "ticked" 0→real; the freshness pill faded in last;
  fully disabled under "reduce motion."
- **Tests:** asserted the top-3 ranking and that the cache is actually used.

**Why reverted:** you preferred the abstract art direction. All of it was undone
cleanly — the reused tile component and the homepage controller are back to their
exact previous state; the new partial and animation CSS were deleted.

**What survived the revert:** the caching lesson (see Technical Debt + Learning
Path) and the three smoke tests.

## Decision Register

- **Hero visual = abstract brand art, not a real-venue showcase.** We tried three
  concrete real-data directions (a live map with one real featured venue card; a
  three-real-tile animated stack) and one abstract direction. Chosen: **abstract
  low-fi cluster.** Rejected: the single real card (looked flat and, with current
  seed data, sparse), and the three-real-tile stack (strong, but tied the hero's
  look to whichever venue happens to rank first — and seed data makes that
  unpredictable). Status: **Decided for now**, revisit once real venue data
  (good photos/breadth) exists — a real-tile hero becomes compelling then.

- **Cache database *IDs*, never hydrated model objects.** When the tile-stack
  feature cached the top-3 venues, the page 500'd in the real app with
  `__PHP_Incomplete_Class`. Root cause: this app's cache lives in the **database**,
  and the database cache driver does **not** reliably round-trip Eloquent model
  objects (even a single one). Fix pattern: cache the list of **IDs** (plain
  numbers, safe in any cache), then re-load the records each request. Status:
  **permanent rule** for this codebase, even though the feature that revealed it
  was reverted.

- **Hero graphic stays desktop-only (`hidden lg:flex`).** Matched the existing
  hero's behaviour rather than introducing a mobile variant. Rejected: showing a
  single tile/card on phones — adds weight to the most performance-sensitive
  view for little gain. Status: Decided; revisit if we want a mobile hero visual.

- **Reused the shared venue-tile via opt-in flags (during the tile-stack build).**
  Rather than fork the tile, added default-off flags so the discovery map was
  untouched. Sound approach — noting it because the *pattern* (extend a shared
  component with gated, default-off props) is the right way to reuse map-coupled
  UI elsewhere. Status: superseded by the revert, but the pattern stands.

- **First impression fixed.** The homepage is the product's business card and the
  top of every acquisition funnel (Instagram → link in bio → homepage). Replacing

  breaks the front page gets caught in CI, not by a user.

## Learning Path

- **Why caching models breaks (and IDs don't).** When Laravel stores something in
  the *database* cache, it converts the object to a text blob and back. Full model
  objects don't survive that round-trip cleanly; plain numbers (IDs) always do.
  The habit to build: cache *identifiers*, then re-fetch the records. Search terms:
  "Laravel cache Eloquent model serialization", "`__PHP_Incomplete_Class`".
- **Why "tests passed but prod broke."** Test environments use a fast in-memory
  cache that skips the text conversion, so the bug was invisible in tests. Lesson:
  test environments should mirror production for the things that only fail in
  production (here, the cache driver).
- **Tailwind's "build-time" nature.** Tailwind only generates the styles it can
  *see written literally* in the code. Styles assembled from variables at runtime
  don't exist. When a size/position must be dynamic, use an inline `style`
  attribute instead of a dynamic class. This was the mesh-pin bug.
- **Reduced-motion accessibility.** Animations should respect the OS "reduce
  motion" setting — the reverted tile animation did (final state shown instantly).
  Worth keeping as a standard for any future animation.
