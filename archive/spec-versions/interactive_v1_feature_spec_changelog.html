Freshness Loop Changes
How the 90-day cycle actually works
Freshness Threshold Configuration
Changed
Spec
Hard-coded 90 days
Actual
Configurable via config('uni.freshness_days') with UNI_FRESHNESS_DAYS env variable. Default: 90
Badge Loss Mechanism
Changed
Spec
Verified badge is removed. Venue demoted in default sort (stale venues always below fresh). No email in v1
Actual
Freshness is a computed property (freshness_state accessor), not stored. Visual indicator changes color (green→red). is_verified is NOT automatically removed by staleness — it's a separate admin-controlled flag. Hourly artisan command (uni:check-offer-freshness) detects drift and recalculates scores
Confirmation Mechanism
Changed
Spec
Panel banner with single "Confirm now" button for whole menu
Actual
FreshnessRelationManager in owner panel — per-product confirmation of availability (individual confirmed_at on venue_products pivot). VenueStatusWidget on dashboard shows overall status. PostHog product_confirmed event with days_since_last_confirm
Observers Auto-Update Freshness
Added
Not detailed in spec. VenueProductObserver and VenueDrinkObserver automatically set offer_updated_at = NOW() on any product/drink add, remove, or edit.
