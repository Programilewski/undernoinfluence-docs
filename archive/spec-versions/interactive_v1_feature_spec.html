Discovery Page /szukaj
The core product — map + filterable venue list
Interactive Map
P0
Leaflet.js map centered on Warsaw. Venue markers as colored dots (not cluster blobs in v1). Click a dot → opens venue card preview anchored to the sidebar list.
  • Color-coded dots per primary drink category (beer amber, wine pink, etc.)
  • Map state syncs with active filters — filtered-out venues disappear from map
  • GPS "Near Me" button — requests browser geolocation, recenters map
  • Mobile: map takes 50% viewport, list is scrollable below
Venue List
P0
Sidebar list of matching venues. Each card shows: venue name, district, type (bar / restaurant / café), breadth score, category chunks, and freshness badge.
  • Default sort: breadth score desc, then name alpha
  • User can switch to: Name A–Z, Distance (requires geolocation)
  • Chunk visualization: colored squares showing products per category
  • Verified badge shown on card; Stale venues clearly dimmed
Breadth Score Chunk Visualization
The visual identity of UNI. Each colored square = 1 product in that category. A venue with 4 beers, 2 wines, 1 cocktail renders as a distinctive pattern. Users learn to read these at a glance.

Sort 1
Breadth Score
Default. Ranks by breadth_score column (denormalized int, auto-recalculated on product add/remove). Tiebreaker: category count diversity.

Sort 2
Distance
Requires browser geolocation consent. Falls back to breadth sort if denied. Distance from user's GPS to venues.coordinates (lat/lng). Computed client-side.
Requires GPS
Sort 3 + Search
Name / Keyword
Text input. Searches venues.name, address, and product names. Full-text index in PostgreSQL. Debounced 300ms. Also enables alphabetical sort (A–Z).
Full-text PG300ms debounce
Filter Behavior Rules

All filters are AND logic (beer AND Mokotów AND verified). Filter state is preserved in URL query params for shareability and browser back button. No filter = all venues shown, sorted by breadth. Filters update the map and list simultaneously via Livewire reactive state — no page reload.

Venue Profile Page /miejsce/{slug}
What the end user sees when they choose a venue
Venue Header & Identity
P0
Name, venue type (bar / restaurant / café / pub), district + full address, interactive mini-map showing pin, Get Directions button (opens Google Maps with coordinates). No venue photos in v1.
Freshness + Verified Badges
P0
Binary freshness indicator: Świeże (confirmed within 90 days) or Nieaktualne (stale). Verified badge (owner has claimed and maintains). Stale data shown transparently, not hidden.
  • Source: venues.offer_updated_at compared to NOW() − 90 days
  • Stale badge shows last-confirmed date to let user judge recency
  • Verified badge: venues.is_claimed = true
Category Breadth Chart
P0
Visual grid of colored chunks per category — the visual identity of UNI. Shows at a glance which categories are strong (many chunks) vs token presence (1 chunk).
  • Source: COUNT of products per category from venue_products join
  • Categories with 0 products are greyed out, not hidden
  • Custom house drinks (mocktails) counted in relevant category
Full Product List
P0
Complete named list of all NA products offered. Grouped by category. Shows brand, product name, and category badge. Custom house drinks listed separately with description.
  • Source: venue_products → global products catalog
  • Custom drinks: venue_drinks table (name, description, type)
  • No prices — price data is stale risk, not worth the maintenance burden
  • No opening hours — Google Maps is SSOT; stale hours damage trust
Nearby Venues
P1
3–5 nearest venues within 1km radius. Sorted by distance. Shows name + breadth score. Source: PostGIS distance query from this venue's coordinates.
Suggest a correction
P1
Link to a minimal form where users can flag stale or wrong data. Submissions go to admin queue — not shown publicly. Acts as a data quality signal without opening user-edit abuse.

Owner Panel: Product Management
Adding, removing, and proposing products from the catalog
Attach from Global Catalog
P0
Owner searches the curated global products catalog (name, brand, category). Select → product is attached to venue_products. No duplication — each product exists once globally.
  • Catalog: brand, product name, category, ABV, country of origin
  • Typeahead search on product name + brand
  • Filter catalog by category before searching
  • Attaching a product auto-triggers breadth score recalculation
Propose New Product
P0
Product not in catalog? Owner submits a proposal (name, brand, category, optional notes). Goes to product_proposals queue. Admin reviews and adds to global catalog, then notifies owner. Product is NOT on venue listing until approved.
  • Prevents catalog pollution with duplicates/variations
  • Owner sees "pending approval" state in their panel
  • Admin deduplicates against existing catalog on review
Add Custom House Drinks
P0
Mocktails and house-made NA drinks that aren't branded products. Owner enters: name, description (e.g., "cucumber mint lemonade with elderflower"), type (Mocktail / Virgin Classic / NA Spirit-Based / Other).
  • Stored in venue_drinks table, not global catalog
  • Counted in breadth score under relevant category
  • No photos in v1
Remove Product
P0
One-click detach of a product from the venue. Immutably logged to venue_offer_logs (what, when, by whom). Breadth score recalculated immediately. No confirmation modal — undo is "add it back."
Offer Audit Log
P1
Immutable log of every add/remove action. Visible to admin only (not owner in v1). Used for trust verification and abuse detection.

Freshness Confirmation Loop
The engagement mechanism that keeps data current
Design Intent

The freshness model creates a natural re-engagement cycle without UNI needing to nag owners. The Verified badge = visibility reward. Losing it = demotion signal. This makes data maintenance self-incentivizing rather than administrative burden.

01
Clock Starts on Product Change or Manual Confirm
venues.offer_updated_at is set to NOW() when: any product is added or removed, any house drink is added/removed/edited, or owner clicks "Confirm current menu is up to date".
02
Day 90 — Badge Drops
If offer_updated_at < NOW() − 90 days: Verified badge is removed from public listing. Venue is demoted in default sort (breadth score tie-breaks resolved against stale venues). No automated email in v1 — badge loss IS the signal.
auto-computedno nag email v1sort demotion
03
Owner Logs In → Sees Badge Warning
Panel banner: "Your menu hasn't been confirmed in 90+ days. Your Verified badge is inactive. Customers may not trust your data. [Confirm now →]"
in-panel banner1-click action
04
Confirmation → Badge Restores Instantly
Owner clicks confirm. offer_updated_at = NOW(). Badge reactivates on public listing immediately. Sort position restores. No admin review needed.

Scoring Logic
How venues are ranked — the algorithm behind the default sort
Breadth Score
P0
Primary ranking signal. Count of total distinct products (catalog products + custom house drinks). Stored as a denormalized integer column venues.breadth_score. Auto-recalculated via DB trigger on product add/remove.
  • 5 beers + 3 wines + 2 cocktails + 1 spirit = breadth_score: 11
  • 11 beers = breadth_score: 11, but lower category diversity (tiebreaker)
  • Indexed column → fast ORDER BY without live count query
Category Diversity Tiebreaker
P1
When breadth scores are equal, venues with more distinct categories rank higher. Computed from COUNT(DISTINCT category_id) in venue_products. NOT part of the main score formula — tiebreaker only.
Freshness Modifier
P0
Stale venues (offer_updated_at > 90 days ago) are demoted in default sort behind all fresh venues regardless of breadth score. Fresh venues always float above stale ones.
Admin Verified Flag
P1
Manual admin toggle: UNI team has independently verified this venue exists and data is accurate. Separate from owner freshness (automated) and claimed status (owner action). Shown as a distinct signal to users — highest trust tier.

Analytics (PostHog)
11 tracked events — data collection for v2 features and B2B pitches
Why track in v1

Analytics data collected in v1 becomes the product in v2. "47 users searched for NA wine in Mokotów this month" is the cold email hook. Category demand by district is the premium dashboard feature. The data flywheel starts on day 1 even though owners don't see it yet.

Tracked Events (11 total)
  • venue_viewed — venue_id, district, category count
  • filter_applied — filter type (category/district/verified), value selected
  • search_performed — query string, result count returned
  • directions_clicked — venue_id, source (map/profile)
  • category_page_viewed — category slug
  • district_page_viewed — district slug
  • claim_started — venue_id
  • claim_submitted — venue_id, verification method
  • product_added — product_id, category, venue_id (owner panel)
  • freshness_confirmed — venue_id, days_since_last_confirm
  • correction_submitted — venue_id, type
